## 1. 背景と目的

- QLoop は 1 問 1 答形式で勉強するためのアプリ。教材（問題集）は日本史の年表、語彙、英単語、日本地理。年表・語彙・日本地理は中学受験（関東圏・易しい〜早慶/MARCH 付属レベル）の範囲を対象にし、英単語は利用者が用意する本とレッスンごとの一覧を対象にする。将来は高校受験の範囲や他の教科への拡張を見込む。
- 教材は複数持てる。1.0 は日本史年表だけで、1.1 で語彙（まず慣用句）を足し、1.3 で英単語を 3 つ目の種類の教材として足し、1.5 で日本地理（地図の画像を見て地名を答える）を 4 つ目の種類として足す（5 章の冒頭・5.8 節・5.9 節・6.11 節・6.12 節）。
- URL を知った人が誰でも使える公開アプリとして配信する。広報はせず、無料の範囲で運用する。
- PWA（ホーム画面に追加して使う Web アプリ）として作り、Cloudflare の静的配信から配る。各端末は Safari で URL を開いて「ホーム画面に追加」するだけで導入でき、更新は配信側に置くだけで全端末に行き渡る。署名や再署名の運用は発生しない。
- 成績は端末ごとに持ち、ログインや端末間の同期はしない。学習データは端末の外に出ない。
- 動作保証の下限は iOS 15.8 の Safari（iPhone 7 で使える最後の版）とする。Android や PC のブラウザでも動くが、受け入れ確認の対象は iOS の Safari に限る。

## 2. 機能要件（確定分）

1. 出題パターン A「年号入力」: 出来事を表示し、年号を数字で入力させる。完全一致で正解（複数の正答年を持つ出来事はいずれかに一致で正解）。判定の後は正解の年を表示する（ずれの年数は表示しない）。
2. 出題パターン B「出来事 4 択」: 年号を表示し、出来事を 4 択で選ばせる。誤答の選択肢は正解と近い年代の出来事から選ぶ。
3. 出題パターンの選択: セッション開始時に「年号入力 / 年号 4 択 / 出来事 4 択 / ミックス」から選ぶ。
4. 出題範囲の指定: 「全範囲」「年号の範囲（ここから〜ここまで）」「時代（複数選択可）」の 3 通り。
5. 復習モード: 最近間違えた問題を重点的に出題する。続けて正解した問題は外す（7 章）。
6. 成績: 項目ごとの正答率を保持し、全体・時代別（語彙は種類別）・項目別・セッション履歴を表示する。
7. 成績の書き出し（JSON）、読み込み（復元）、リセットができる。
8. データ: 初期データ（年号 - 出来事）は利用者が CSV で用意する（100〜200 件）。中学受験の範囲の出来事を追加データとして別途作成し、出来事 4 択の誤答の候補に使うとともに出題対象にもできる（出題設定で「基本の年表のみ / すべて」を選ぶ）。将来は合計で千数百件まで増える想定。
9. 初回表示の後はオフラインでも動く。
10. 画面は日本語のみ。ふりがなは付けない（語彙の読みは問題文には出さず、判定の後と結果・成績の一覧に出す。5.7 節）。小学校高学年以上を想定し、通常の大人向け表示でよい。
11. アプリ内でのデータ編集機能は作らない。
12. ホーム画面の「アプリを更新」で、新しい版を探して切り替えられる（6.6 節）。
13. 出題パターン C「年号 4 択」: 出来事を表示し、年号を 4 択で選ばせる。誤答の年は正解の前後 1〜10 年から選ぶ（6.7 節）。
14. 年号入力・年号 4 択・出来事 4 択のどれでも「わからない」を選べる。不正解として記録し、答えを見せて先へ進める（入力できないときの逃げ道）。
15. 教材の切り替え（1.1）: ホームで教材（日本史年表 / 語彙）を選ぶ。出題・復習・成績は選んだ教材のもの（6.9 節）。
16. 語彙の出題パターン（1.1）: D「意味 4 択」（言葉を見せて意味を 4 択で選ぶ）と E「言葉 4 択」（意味を見せて言葉を 4 択で選ぶ）、両方をまぜるミックス。「わからない」も同じように選べる（6.8 節）。
17. 語彙の範囲の指定（1.1）: 「全範囲」「種類（複数選択可）」の 2 通り。
18. 語彙のデータ（1.1）: 基本データは利用者が言葉と意味の一覧で用意し、追加データ（誤答の候補と「すべて」での出題）を別途作成する。まず慣用句（5.7 節、`docs/data.md` の 6 章）。
19. 一覧（1.2）: ホームで選んだ教材の母集団を、年表は時代ごと、語彙は種類ごとの見出しで並べて眺められる。表示する項目（基本のみ / すべて）と時代（語彙は種類）で絞り込める。年か出来事（語彙は意味か言葉）を隠し、行を押すとその行だけ出す暗記カードとして使える（6.10 節）。
20. 結果画面から一覧へ（1.2）: 結果画面の「間違えた項目」の行を押すと、一覧のその項目に移って強調し、「戻る」で結果画面に戻る（6.4 節の 6、6.10 節）。
21. 英単語の教材（1.3）: 3 つ目の教材「英単語」。本（STAGE1 / STAGE2 / STAGE3）とレッスンの一覧で、レッスンごとに段階的にデータを足す。追加データと「基本のみ / すべて」の切り替えは無い（5.8 節）。
22. 英単語の出題パターン（1.3）: F「意味 4 択」（英単語を見て意味を 4 択で選ぶ）と G「英単語 4 択」（意味を見て英単語を 4 択で選ぶ）、両方をまぜるミックス。誤答は同じ品詞の英単語を優先する（6.11 節）。H「つづり入力」（意味を見て英単語を打つ）を 1.4 で足し、ミックスは 3 つのパターンをまぜる。
23. 英単語の範囲の指定（1.3）: 「全範囲」「レッスン（複数選択可）」の 2 通り。レッスンは本ごとの見出しの下から選ぶ。
24. 英単語の一覧（1.3）: 「英単語を覚える」。レッスンごとの見出しの下に一覧に入れた順で並べ、意味の頭に品詞の略記を付ける（6.10 節）。
25. アプリの更新の進み具合（1.4.1）: 新しい版の読み込み（事前キャッシュの取得）の間、ホームに進み具合を横棒と百分率で出す（6.6 節）。
26. 日本地理の教材（1.5）: 4 つ目の教材「日本地理」。地図の画像でアで示した地名（山地・山脈、山、平野・盆地・台地、川・湖、半島・岬、島、海・湾・海流、都道府県庁所在地）を答える。基本の地名 142 件と追加データ 168 件で、「基本の地名のみ / すべて」を選べる（5.9 節）。
27. 日本地理の出題パターン（1.5）: I「名前 4 択」（地図を見て名前を 4 つから選ぶ）と J「名前入力」（地図を見て名前を打つ。漢字でもひらがなでも正解）、両方をまぜるミックス。「わからない」も同じように選べる（6.12 節）。
28. 日本地理の範囲の指定（1.5）: 「全範囲」「分類（複数選択可）」の 2 通り。分類は 8 つのまとめ（5.9 節）。
29. 日本地理の一覧（1.5）: 「地図で覚える」。分類のまとめごとの見出しの下に名前・読みと地図を並べ、名前か地図を隠して暗記カードとしても使う（6.10 節）。

## 3. 技術方針

| 項目 | 決定 | 理由 |
|---|---|---|
| 言語 | TypeScript（strict） | 型でデータ形式と状態遷移を固定する |
| ビルド | Vite | 標準的で設定が少ない。`build.target` を `safari15` にする |
| UI | React（最新安定版。関数コンポーネントと hooks） | もっとも標準的で、実装の委譲先が扱いやすい。画面遷移はアプリ内の状態で持ち、ルーティングライブラリは使わない |
| PWA | `vite-plugin-pwa`（Workbox。1.4.1 から `injectManifest` で自前の Service Worker `src/sw.ts`） | ビルド成果物・同梱データ・地図の画像を事前キャッシュしてオフラインで動かす。更新は `prompt` 方式で、読み込みの進み具合を画面に知らせる（6.6 節・9.2 節） |
| 保存 | IndexedDB（`idb` で Promise 化） | 非同期・大容量・索引付き。レコード単位の追記に向く（5.4 節） |
| テスト | vitest（`src/core`・`src/storage`）、Playwright の WebKit（主要な画面の通し確認） | ロジックは Node 上で決定的に検証し、画面は Mac 上のヘッドレス WebKit で確認する |
| 整形と静的検査 | ESLint（typescript-eslint の recommended）と Prettier | 既定設定のみ。独自ルールは足さない |
| 配信 | Cloudflare Workers の静的アセット配信（`wrangler deploy`） | 無料枠で静的配信の帯域は無制限。HTTPS 付き。Pages の後継として新規に推奨されている方式 |
| ブラウザの下限 | iOS 15.8 の Safari | iPhone 7 の最終 OS。これより新しい API は使わない（9.4 節） |

- 乱数は `src/core` の関数に注入できるようにし、テストでは固定シードの生成器を渡す。
- 現在時刻と暦（タイムゾーン）も注入できるようにし、日付境界のテストを可能にする。
- Playwright の WebKit は最新の WebKit であり、iOS 15.8 の Safari と同一ではない。iOS 15.8 固有の非互換は iPhone 7 の実機確認で拾う（各 PR の受け入れ基準に含める）。
- Node.js は 22 以上（`package.json` の `engines`）。TypeScript は 6.0 系に固定する（typescript-eslint の対応範囲が 6.1 未満のため。対応したら上げる）。

## 5. データ設計

教材（Deck）の構造。1.0 は年表 1 つに固定していたが、1.1 で複数の教材を持てるようにした。

- 教材は `{ id, kind, name, items }`。`kind`（教材の種類）は `timeline`（年表）、`vocabulary`（言葉と意味）、`english`（英単語。1.3）、`geography`（日本地理。1.5）。教材の一覧はコードの定数で持ち、1.0 の `japanese-history`（年表。表示名「日本史年表」）に、1.1 で `japanese-vocabulary`（言葉と意味。表示名「語彙」）を足し、1.3 で `english-words`（英単語。表示名「英単語」）を足し、1.5 で `japanese-geography`（日本地理。表示名「日本地理」）を足す。英単語を `vocabulary` の 2 つ目の教材にせず 3 つ目の種類にする理由は 5.8 節、日本地理を 4 つ目の種類にする理由は 5.9 節。
- 項目（item）は教材の 1 行で、年表では出来事（Event。5.1 節）、語彙では言葉（Word。5.7 節）、英単語では英単語（EnglishWord。5.8 節）、日本地理では地名（GeoPlace。5.9 節）。項目は `id`・`level`・`role`（`core` / `pool`）を共通に持ち、記録はこの `id` に紐づく。
- 教材の種類ごとに違うものは次の表のとおり。種類ごとの 1 か所（年表は `deck.ts`・`quiz.ts`・`range.ts`、語彙は `vocabulary.ts`、英単語は `english.ts`、日本地理は `geography.ts`）にまとめ、`decks.ts` で振り分ける。記録・セッション・復習・成績・書き出しは、教材の種類を知らずに動く。

| 違うもの | 年表 | 言葉と意味 | 英単語（1.3） | 日本地理（1.5） |
|---|---|---|---|---|
| 項目の型と CSV の列 | Event（5.1 節） | Word（5.7 節） | EnglishWord（5.8 節） | GeoPlace（5.9 節） |
| 追加データ（`pool.csv`）と「基本のみ / すべて」の切り替え | あり | あり | 無し（`core.csv` だけ。全行が基本データ） | あり |
| 出題パターン | 年号入力・年号 4 択・出来事 4 択 | 意味 4 択・言葉 4 択 | 意味 4 択・英単語 4 択・つづり入力（1.4） | 名前 4 択・名前入力 |
| 範囲の指定 | 全範囲・年号の範囲・時代 | 全範囲・種類 | 全範囲・レッスン | 全範囲・分類 |
| まとめる単位（成績の内訳と、誤答の候補の単位） | 時代 | 種類 | レッスン（本と番号。誤答の候補は全レッスンから） | 分類のまとめ（8 つ。誤答の候補は分類と地方で優先） |
| 適格判定と選択肢の作り方 | 6.1〜6.3 節・6.7 節 | 6.8 節 | 6.11 節 | 6.12 節 |
| 画面の言葉 | 出来事、基本の年表 | 言葉、基本の語彙 | 英単語（基本データの呼び名は無い） | 地名、基本の地名 |
| 一覧（6.10 節）の名前・見出し・行・隠すもの・並び順 | 「年表を覚える」。時代の見出し。行は年と題名。隠すのは年か出来事。年の順 | 「言葉を覚える」。種類の見出し。行は言葉と読みと意味。隠すのは意味か言葉。読みの五十音順 | 「英単語を覚える」。レッスンの見出し。行は英単語と、品詞の略記付きの意味。隠すのは意味か英単語。一覧に入れた順（id の順） | 「地図で覚える」。分類のまとめの見出し。行は名前と読みと地図。隠すのは名前か地図。id の順 |

- ビルドは全教材の CSV を検証して `src/generated/decks.json`（教材の配列）に書く。

### 5.1 出来事（Event）

年表の教材の項目。CSV の列は次のとおり。`core.csv` と `pool.csv` で同じ形式を使う。どちらのファイルにあるかで区分（基本の年表 = 初期データ / 追加データ）が決まる。出来事 4 択の誤答の候補には両方を使う。

| 列 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | 全ファイルを通して一意な文字列。本番データは `jh-0001` の形式。成績はこの id に紐づく（5.5 節の規則に従う） |
| `year` | 必須 | 整数。0 は不可。紀元前は負数（紀元前 4 世紀ごろ → `-350` など代表年。紀元前 4 世紀は紀元前 400〜301 年） |
| `title` | 必須 | 出来事の文。全ファイルを通して重複不可 |
| `era` | 任意 | 時代の上書き。空なら `year` から時代区分表で決める |
| `approx` | 任意 | `1` なら「ごろ」の出来事。年号入力と年号 4 択の出題対象から外し、表示は 5.3 節の規則に従う |
| `alt_years` | 任意 | 追加で正解とみなす年。`;` 区切り。題名全体に対して正解といえる年だけを書く |
| `year_label` | 任意 | 年の表示を上書きする文字列（例 `紀元前4世紀ごろ`、`3世紀`）。空なら 5.3 節の既定の表示 |
| `level` | 任意 | `中学` または `高校`。空は `中学`。v1 では `高校` の行を出題対象から外す（誤答の候補には使う） |

例:

```
id,year,title,era,approx,alt_years,year_label,level
jh-0001,710,平城京に都を移す,,,,,
jh-0042,1185,鎌倉幕府の成立,鎌倉,,1192,,
jh-0300,-350,稲作が伝わる,弥生,1,,紀元前4世紀ごろ,
```

- 年表データの「正しさ」は、歴史的な史実ではなく、現代の中学受験・高校受験で出題される問題での正解とする（絶対の方針）。この基準、列の使い分け（別解・ごろ・時代の上書き・`高校`）、データを足す手順、確定した個別の判断は `docs/data.md` にまとめる。
- 同じ年に複数の出来事があってよい。

CSV の形式: UTF-8（先頭の BOM は許容）、改行は LF と CRLF のどちらでもよい、1 行目は上の 8 列のヘッダー（必須・順序固定）、「任意」は空セル可の意味で列自体は省略しない、セル内のカンマと `"` は `"..."` で囲んで `""` でエスケープする、セル内の改行は使わない（検出したらエラー）。

### 5.2 検証（`scripts/build-data.ts` とテストで自動確認）

- `id` と `title` が全ファイルを通して一意であること。`id` は `jh-` で始まること。
- `year` が 0 以外の整数であること。`alt_years` が整数で `year` と異なること。
- `era` に書かれた時代名が時代区分表にあること。`approx` が `1` か空であること。`level` が `中学`・`高校`・空のいずれかであること。
- `core.csv` の全行（出題対象）について、出来事 4 択の誤答候補が 3 件以上あること（6.3 節の除外規則を適用した後の件数）。
- 検証に失敗したらビルドを止める。データを編集した PR はこの検証で守る。
- 語彙の検証は 5.7 節。教材ごとに検証し、エラーは教材名・ファイル名・行番号付きで全件を出す。

### 5.3 年の表示と時代区分表

年の表示は 1 か所の関数にまとめ、出題・判定後の表示・まとめ・成績で共通に使う。

- `year_label` があればそれを使う。
- なければ、`approx` なら「○○年ごろ」、そうでなければ「○○年」。紀元前は「紀元前○○年」「紀元前○○年ごろ」。

`era` が空の出来事は、`year` が次の開始年以上で、次の時代の開始年未満なら、その時代に属するとする。

| 時代 | 開始年 | 補足 |
|---|---|---|
| 縄文 | （弥生より前） | 年が確定する出来事はほぼ無い |
| 弥生 | -400 | 紀元前 4 世紀ごろから |
| 古墳 | 250 | 3 世紀中ごろから |
| 飛鳥 | 592 | 推古天皇の即位 |
| 奈良 | 710 | 平城京 |
| 平安 | 794 | 平安京 |
| 鎌倉 | 1185 | 守護・地頭の設置 |
| 室町 | 1334 | 建武の新政を室町に含める。1333 年の鎌倉幕府滅亡は鎌倉に入る |
| 安土桃山 | 1573 | 室町幕府の滅亡 |
| 江戸 | 1603 | 江戸幕府 |
| 明治 | 1868 | |
| 大正 | 1912 | |
| 昭和 | 1926 | |
| 平成 | 1989 | |
| 令和 | 2019 | |

- 南北朝・戦国は室町に含める。旧石器は対象外（初期データに該当する行は無かった）。
- 境界の年で表と感覚が合わない出来事（例: 1185 年の壇ノ浦の戦い → 平安、1573 年の室町幕府の滅亡 → 室町）は、データ側の `era` 列で上書きする。
- 時代による範囲指定は、この表ではなく各出来事の確定した時代（上書きを反映したもの）で絞り込む。

### 5.4 成績の保存（IndexedDB）

データベース名 `qloop`、版 1。ストアと索引は次のとおり。

| ストア | キー | 内容 |
|---|---|---|
| `attempts` | `id`（自動採番） | 回答の記録。`eventId`（項目の id。語彙では言葉の id。名前は 1.0 の記録を引き継ぐため変えない）、`pattern`（`yearInput` = 年号入力 / `yearChoice` = 年号 4 択 / `choice` = 出来事 4 択 / `meaningChoice` = 意味 4 択 / `wordChoice` = 言葉 4 択 / `englishMeaningChoice` = 英単語の意味 4 択 / `englishWordChoice` = 英単語 4 択 / `englishSpelling` = つづり入力（1.4） / `geoNameChoice` = 日本地理の名前 4 択 / `geoNameInput` = 日本地理の名前入力（1.5）。英単語と日本地理の識別子を語彙と分けるのは、問題の型をパターンで見分けられるようにするため）、`correct`、`answeredAt`（UTC の ISO 8601 文字列）、`sessionId`。索引: `byEvent`(eventId)、`byAnsweredAt`(answeredAt)、`bySession`(sessionId)。追記のみで、これが正本 |
| `eventStats` | `[eventId, pattern]` | 項目 × パターンの集計。`attempts`（回答数）、`correct`、`lastAnsweredAt`、`lastCorrect`、`lastWrongAt`、`consecutiveCorrect`（最後に間違えた後に続けて正解した回数。最後の回答が不正解なら 0。1.1.1 で追加）。成績画面と復習はこれを読む |
| `sessions` | `id`（UUID） | `deckId`（教材の id。1.1 で追加。1.0 の記録には無いので、読むときに `japanese-history` とみなす）、`mode`（`normal` / `review`）、`pattern`（5.4 節のパターンか `mixed`。復習は `null`）、`range`（年表は `all` / `years` / `eras`、語彙・英単語・日本地理は `all` / `categories`（`{ kind: 'categories', categories: string[] }`。英単語の値はレッスンの名前「STAGE2 Lesson 4」（5.8 節）、日本地理の値は分類のまとめの名前「川・湖」（5.9 節））。復習は範囲を選ばないので `null`）、`startedAt`、`endedAt`（未終了は `null`）、`total`（生成した問題数）、`answered`、`correct` |
| `meta` | `key` | `settings:<教材の id>`（教材ごとの出題設定。最後に選んだ出題する項目・パターン・問題数・範囲。1.1 で追加）、`settings`（1.0 の年表の出題設定。読むときだけ使い、`settings:japanese-history` が無いときの初期値にする）、`lastDeck`（ホームで最後に選んだ教材の id。1.1 で追加）、`studyDays`（回答のあった端末ローカルの暦日 `YYYY-MM-DD` の一覧。全教材で共通） |

- 1 回答ごとに 1 つのトランザクションで、`attempts` への追記、`eventStats` の更新、`sessions` の `answered`・`correct` の更新、`meta.studyDays` の更新を行う。
- 回答前のセッションが、別の画面の起動時の掃除（6.4 節の 7）で消えていることがある。そのときは、回答や終了を保存するトランザクションの中で、メモリ上の同じセッションを書き戻してから記録する。
- `eventStats`・`sessions` の件数・`studyDays` は `attempts` から再計算できる（`rebuild()`）。読み込み（復元）の後に必ず実行する。
- 1.1.1 より前の `eventStats` には `consecutiveCorrect` が無い。`ProgressStore.load()` で無いものが 1 件でもあれば、1.1.1 の最初の起動で `attempts` から `rebuild()` と同じ処理で 1 回だけ数え直し、IndexedDB にも書く。次の起動では数え直さない。失敗しても起動は止めず、メモリ上で無い値を 0 とみなし、次の起動でまた数え直す。
- 成績の状態は 1 つの `ProgressStore` が持つ。回答を保存したら同じオブジェクトの中の集計を更新し、成績画面と復習の候補選定はそこから読む。起動時の読み込みは `eventStats`・`sessions`・`meta` だけで、`attempts` の全件は読まない（上記の 1.1.1 より前の記録の数え直しだけは例外）。
- 現在のデータ（`decks.json`）に存在しない `eventId` の記録は保持する。除外するのは `eventStats` から作る表示（全体・時代別または種類別・項目別の成績と復習の候補）だけで、セッション履歴（`sessions` の `answered`・`correct`）と `studyDays` は活動の記録としてそのまま使い、データ更新に伴う再計算はしない。
- `attempts`・`eventStats` に教材の id は持たない。成績と復習は選んだ教材の母集団（項目の id の集合）で絞るので、教材ごとの表示はそれで分かれる。教材が要るのはセッション（履歴の絞り込み）と出題設定だけなので、`sessions.deckId` と `meta` の鍵にだけ足す。
- `navigator.storage.persist()` が使える環境では起動時に 1 回呼ぶ。効果は保証されないので頼りにしない。
- データベースを開けなかった場合は、理由を表示して学習を始められないようにする（ごくまれなので復旧機能は作らない）。
- スキーマの変更は IndexedDB の版番号を上げ、`db.ts` の upgrade 処理に移行を書く。
- 出来事 4 択の識別子は、0.1 系の記録を引き継ぐため `choice` のままにする（年号 4 択を足した 0.2.0 で表示名だけを「4 択」から「出来事 4 択」に変えた）。パターンを足しても保存の形は変わらないので、版番号は上げない。1.1 の `sessions.deckId` と `meta` の鍵の追加も、ストアと索引は変わらないので版番号は上げず、無い値は読むときに補う（`settings.scope` と同じ扱い）。1.1.1 の `eventStats.consecutiveCorrect` の追加もストアと索引は変わらないので版番号は上げず、読むときに数え直して補う。1.3・1.4 の英単語と 1.5 の日本地理のパターンの追加も同じ（値が増えるだけ）。

### 5.5 id の規則

- id は並べ替え・表記の修正・年の訂正・`core.csv` と `pool.csv` の間の移動で変えない。削除した id は再利用しない。
- 仮データ（`demo-`）は D1 で削除し、id の接頭辞の検証も `jh-` だけにした。仮データに対する回答は 5.4 節の「存在しない id」として扱われる。
- 利用者の年表を取り込み直す場合は、既存の正本と `title` で照合して差分だけ追加し、全件を振り直さない（`docs/data.md` の 4 章）。
- id の接頭辞は教材ごとに決め、教材の定義に持つ（年表は `jh-`、語彙は `jv-`、英単語は `en-`、日本地理は `jg-`。5.7〜5.9 節）。項目の id は全教材を通して一意になる。

### 5.6 書き出しと読み込み

ホームの下部の「記録の管理」から開く画面で行う。1.3.2 で成績の画面から移した。全教材の記録をまとめて扱うので、教材ごとの画面には置かない。

画面の上部は「戻る」と見出し「記録の管理」で、見出しの下に教材名は出さない。「戻る」でホームへ戻る。見出しの下に「日本史年表・語彙・英単語・日本地理の学習の記録を、まとめて書き出し・読み込み・リセットします。」と出す（教材名は教材の定義の順に「・」でつなぐ。1.5 で日本地理が加わる）。その下に書き出し・読み込み・リセットの 3 つの行のカード、書き出しの準備の欄、ファイル選択、操作の結果の知らせを置く。同じ名前の小見出しは重ねない。読み込みとリセットの確認ダイアログの本文には「すべての教材の」を入れ、対象が全教材であることを示す。処理中（書き出しの準備・ファイルの読み取り・読み込み・リセット）は、3 つの行と「戻る」を押せない。

- 書き出し: `{ "schemaVersion": 2, "exportedAt": "...", "attempts": [...], "sessions": [...] }` を `qloop-progress-YYYYMMDD.json`（日付は端末ローカル）として出す。全教材の記録を 1 つのファイルに入れる。1.1 で `sessions` の各項目に `deckId` を足し、版を 1 から 2 に上げた。操作は 2 段階にする。
  1. 「書き出し」で IndexedDB を読み、ファイルを用意する。用意した欄が出ているときにもう一度押すと欄を閉じ、用意したファイルを捨てる（次に押したときに、その時点の記録で作り直す）。
  2. ファイル共有に対応した `navigator.share` が使えれば「共有して保存」、使えなければ「ファイルを保存」（`<a download>`）で保存する。`navigator.share` は利用者の操作の直後でないと拒否されるので、読み出しの待ち時間を挟まないよう 2 段階に分けている。共有が取り消し以外の理由で失敗したら、「ファイルを保存」に切り替える。
- 読み込み: ファイル選択で JSON を受け取り、形式を検証して、確認ダイアログの後に全置換する。
  - 検証: `schemaVersion` が 1 か 2、`exportedAt` と各項目の型、時刻は ISO 8601（UTC にそろえる）、セッションの `id` の重複は不可。パターンは 5.4 節の値だけを、範囲は年表の形（`years`・`eras`）と語彙・英単語・日本地理の形（`categories`）を受け付ける。時代の範囲は現行どおり時代区分表に照合し、種類とレッスンの範囲（`categories`）は空でない文字列の配列としてだけ検証して、今の種類やレッスンの一覧には照合しない（今の教材に無い記録もそのまま保つため。出題を始めるときの範囲の検証とは別）。1.3・1.4・1.5 で足したパターンの値を含むファイルは、それより前の版のアプリでは読めない（パターンの検証で止まる。全端末を更新する運用なので許容し、版は上げない）。版 1 のファイルは `sessions` に `deckId` が無いので `japanese-history` を補う。版 2 の `deckId` は空でない文字列なら受け付け、今の教材に無い id もそのまま保つ。知らない項目は捨てる。存在しないセッションを指す回答は受け付ける。
  - 1.0 のアプリは版 2 のファイルを読めない（`schemaVersion` の確認で止まる）。全端末を更新する運用なので許容する。
  - 全置換と再計算（`rebuild()` と同じ処理）は 1 つのトランザクションで行い、途中で失敗したら読み込み前の状態に戻る。出題設定（教材ごと）と最後に選んだ教材も消える。
- リセット: 確認ダイアログ（実行のボタンは赤）の後に全ストアを空にし、メモリ上の状態も初期化する。全教材の記録が消える。出題設定も消える。

### 5.7 言葉（語彙の教材の項目）

教材の種類「言葉と意味」の項目。`data/decks/japanese-vocabulary/` の `core.csv`（基本の語彙。利用者がまとめた一覧を整形したもの）と `pool.csv`（追加データ）で同じ形式を使う。誤答の候補には両方を使い、「すべて」で `pool.csv` の `中学` の行も出題する（年表と同じ）。

| 列 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | 全ファイルを通して一意。`jv-0001` の形式（5.5 節の規則に従う） |
| `word` | 必須 | 言葉。全ファイルを通して重複不可 |
| `meaning` | 必須 | 意味。1 文で全角 30 字まで（目安は 25 字まで）。全ファイルを通して重複不可 |
| `category` | 必須 | 種類。種類の一覧にある値 |
| `reading` | 任意 | 読み（ひらがな）。問題文には出さず、判定の後と結果・成績の一覧に出す |
| `level` | 任意 | 年表と同じ。`中学`・`高校`・空（= `中学`）。`高校` の行は出題せず、誤答の候補にだけ使う |
| `similar` | 任意 | 意味が近く、互いの誤答に使えない項目の id。`;` 区切り。片方の行に書けば両方向に効く |

例:

```
id,word,meaning,category,reading,level,similar
jv-0001,浮き足立つ,不安や恐れから落ち着きを失い、逃げ腰になること,慣用句,うきあしだつ,,
jv-0014,腰が重い,気軽に動こうとせず、なかなか行動を起こさないこと,慣用句,こしがおもい,,jv-0002
```

- 種類の一覧はコードの定数で、教材の定義に持つ（並びは成績の種類別と、範囲のチップの順）。1.1 は `慣用句` だけ。ことわざ、熟語（四字熟語と三字熟語。分けるかまとめるかは未定）、和語（扱う問題の中身は確認中）は、データを足すときに名前を確定して一覧に足す。一覧に無い値は検証で止める。
- Word の型は `{ id, word, meaning, category, reading: string | null, level, role, similar: string[] }`。
- 語彙データの「正しさ」は、辞書の記述や語源ではなく、現代の中学受験・高校受験の問題で正解とされる意味と表記とする（年表と同じ絶対の方針）。基準の詳細、列の使い分けと書き方、データを足す手順、確定した個別の判断は `docs/data.md` の 6 章にまとめる。

検証（`scripts/build-data.ts` とテストで自動確認。5.2 節と同じ段取り）:

- `id`・`word`・`meaning` が全ファイルを通して一意であること。`id` は `jv-` で始まること。
- `category` が種類の一覧にあること。`level` が `中学`・`高校`・空のいずれかであること。
- `meaning` が全角 30 字（コードポイント 30 個）以内であること。
- `similar` の各 id が全ファイルのどこかに存在し、自分自身でないこと。
- `core.csv` の全行について、6.8 節の除外規則を適用した後の誤答の候補が 3 件以上あること。
- CSV の形式は 5.1 節と同じ（UTF-8、改行は LF か CRLF、7 列のヘッダー固定、任意の列も省略しない、カンマと `"` の扱い、セル内の改行は不可）。

### 5.8 英単語（英単語の教材の項目）

教材の種類「英単語」（1.3）の項目。`data/decks/english-words/core.csv` の 1 ファイルで、追加データ（`pool.csv`）は置かない。全行が基本データ（`role` は `core`）で、`level` の列は持たず全行を `中学` とみなす。レッスンごとに行を追記して段階的に増やす（`docs/data.md` の 7 章）。

英単語を語彙（5.7 節）の 2 つ目の教材にせず、3 つ目の種類にする理由: 範囲が本とレッスンの 2 段でデータから決まる、誤答の選び方に品詞を使う、同じ意味の行を許す、読み・`高校`・追加データが無い、一覧の並びが五十音順ではなく一覧に入れた順、意味の上限が違う、画面の言葉が違う。語彙の仕組みにこれだけの条件分岐を足すより、種類ごとの差分（`decks.ts` の `KindRules`）をもう 1 つ持つ方が、共通部分を変えずに済む。

| 列 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | 一意。`en-0001` の形式（5.5 節の規則に従う）。足した順の通し番号で、本とレッスンは含めない（`book`・`lesson` の列に持つ。レッスンの指定を直しても id と学習の記録が変わらないように） |
| `word` | 必須 | 英単語・熟語・表現。利用者の一覧の表記のまま（大文字、ピリオド、アポストロフィ、`What ... for?` のような穴を含む）。同じ `word` は別のレッスンにだけ許す（`word`・`book`・`lesson` の組で一意。同じかどうかは 6.11 節の正規化で比べる） |
| `meaning` | 必須 | 日本語の意味。利用者の一覧の文面のまま（複数の意味の「、」区切り、「～」「…」、かっこの注記、文末の「。」を含む）。全角 50 字まで（目安は 40 字まで）。重複可（同じ意味の行は互いの誤答に使わない。6.11 節） |
| `pos` | 任意 | 品詞。品詞の一覧の値。複数は「・」でつなぐ（例 `名詞・形容詞`）。空は熟語・表現 |
| `book` | 必須 | 本。本の一覧（`STAGE1`・`STAGE2`・`STAGE3`）の値 |
| `lesson` | 必須 | レッスンの番号。正の整数 |
| `similar` | 任意 | 意味が近く、4 択でどちらを選んでも正解と言える項目の id。`;` 区切り。片方の行に書けば両方向に効く。同じ `meaning` の行は書かなくてもつながり、`similar` はつながった行の全部に効く（6.11 節の「同じ答えの集まり」）。4 択の誤答の除外にだけ使い、つづり入力の正解には使わない |

例:

```
id,word,meaning,pos,book,lesson,similar
en-0003,spot,場所、地点,名詞,STAGE2,4,
en-0014,check in,（宿泊・搭乗などの）手続きをする,,STAGE2,4,
en-0045,somebody,誰か,代名詞,STAGE2,4,en-0047
```

- 本の一覧はコードの定数で、並びは `STAGE1`・`STAGE2`・`STAGE3`（本を足すときに一覧に足す。一覧に無い値は検証で止める）。
- レッスンの名前は「STAGE2 Lesson 4」（本、半角空白、`Lesson`、半角空白、番号）。範囲の保存（`categories` の値）、履歴、成績のレッスン別、一覧の見出しに使う。チップでは本ごとの見出しの下に「Lesson 4」とだけ書く。母集団にあるレッスンの一覧は、データから本の順・番号の順に作る（コードの定数には持たない）。
- 品詞の一覧と略記はコードの定数で次のとおり。`pos` の各部分（「・」で区切ったもの）が一覧に無ければ検証で止める。略記は各部分の略記を「・」でつなぐ（`名詞・形容詞` は `名・形`）。

| 品詞 | 名詞 | 動詞 | 形容詞 | 副詞 | 代名詞 | 前置詞 | 接続詞 | 助動詞 | 間投詞 | 冠詞 | 数詞 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 略記 | 名 | 動 | 形 | 副 | 代 | 前 | 接 | 助動 | 間 | 冠 | 数 |

- 品詞付きの意味: 「(名) 場所、地点」の形（半角かっこの略記、半角空白、意味）。`pos` が空なら意味だけ。一覧の 2 段目、結果画面の間違えた一覧、英単語 4 択とつづり入力の問題のカード、成績の英単語別の補足に使う。意味 4 択の選択肢には付けない（4 つとも同じ品詞になることが多く、違うときは手がかりになるため）。
- EnglishWord の型は `{ id, word, meaning, pos: string | null, book, lesson: number, level, role, similar: string[] }`。
- 英単語データの「正しさ」は、利用者が用意した一覧の意味と表記とする。辞書と違うことだけを理由に直さない。列の使い分け、レッスンを足す手順、確定した個別の判断は `docs/data.md` の 7 章にまとめる。

検証（`scripts/build-data.ts` とテストで自動確認。5.2 節と同じ段取り）:

- `id` が一意で `en-` で始まること。`word`・`book`・`lesson` の組が一意であること（`word` は 6.11 節の正規化をした形で比べる）。`id`・`word`・`meaning`・`book`・`lesson` が空でないこと。
- `meaning` が全角 50 字（コードポイント 50 個）以内であること。
- `pos` の各部分が品詞の一覧にあること。`book` が本の一覧にあること。`lesson` が正の整数であること。
- `similar` の各 id がファイルのどこかに存在し、自分自身でないこと。
- 全行について、6.11 節の除外規則を適用した後に、意味 4 択では異なる `meaning` の候補が、英単語 4 択では異なる `word` の候補が、それぞれ 3 件以上あること（追加データが無いので全行が出題対象）。
- CSV の形式は 5.1 節と同じ（UTF-8、改行は LF か CRLF、7 列のヘッダー固定、任意の列も省略しない、カンマと `"` の扱い、セル内の改行は不可）。

### 5.9 地名（日本地理の教材の項目）

教材の種類「日本地理」（1.5）の項目。`data/decks/japanese-geography/` の `core.csv`（基本の地名。利用者が基本と指定した 95 件と都道府県庁所在地 47 件の 142 件）と `pool.csv`（追加データ 168 件）で同じ形式を使う。誤答の候補には両方を使い、「すべて」で `pool.csv` の行も出題する（年表・語彙と同じ）。`level` の列は持たず全行を `中学` とみなす。

日本地理を語彙や英単語の仕組みに載せず 4 つ目の種類にする理由: 問いが地図の画像で、答えが名前（漢字とひらがなのどちらでも正解）、誤答の選び方が分類と地方で決まり、範囲と成績の単位が分類のまとめ（8 つ）で、一覧の行に画像が入る。既存の種類に画像と判定の分岐を足すより、種類ごとの差分（`decks.ts` の `KindRules`）をもう 1 つ持つ方が共通部分を変えずに済む（5.8 節と同じ判断）。

| 列 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | 全ファイルを通して一意。`jg-0001` の形式（5.5 節の規則に従う）。元の一覧の順に `jg-0001`〜`jg-0310` を振る。地図の画像のファイル名にもなる |
| `name` | 必須 | 名前（標準の答え。漢字。例 `信濃川`、`黒潮（日本海流）`、`東経135度`、`札幌市`、`東京`）。全ファイルを通して重複不可。4 択の選択肢にはこの表記をそのまま出す |
| `reading` | 必須 | 読み（ひらがな。例 `しなのがわ`、`くろしお（にほんかいりゅう）`）。名前入力の正解にも使う。判定の後と結果・成績・一覧に出す |
| `category` | 必須 | 分類。分類の一覧（下の表の 20 種類）の値。問いの文の名詞と、名前 4 択の誤答の候補の単位 |
| `regions` | 任意 | 地方。地方の一覧（北海道・東北・関東・中部・近畿・中国・四国・九州・沖縄）の値を `／` でつなぐ（例 `東北／関東`）。全国の沿岸に広がるもの（太平洋、黒潮、対馬海流）は空。誤答の優先と、成績・結果の補足に使う |
| `question` | 必須 | 画面に出す問いの文（例 `地図中のアで示した川の名前は？`）。全角 30 字まで。答えやその一部を含めない |
| `note` | 任意 | 地図の読み方の注記（例 `流路は簡略化して示しています。`）。出題の画面で地図の下に出す。描画の種類ごとに決まった文（`docs/data.md` の 8.3 節）。全角 50 字まで |
| `alt_names` | 任意 | 追加で正解とみなす名前と読み。`;` 区切り（例 `日本海流;にほんかいりゅう;黒潮;くろしお`）。受験でどちらを答えても正解とされるものにだけ書く。名前入力の判定にだけ使い、4 択の選択肢には出さない |
| `similar` | 任意 | 互いの誤答に使えない項目の id。`;` 区切り。片方の行に書けば両方向に効く（同じ川の区間名など） |

例:

```
id,name,reading,category,regions,question,note,alt_names,similar
jg-0128,信濃川,しなのがわ,河川,中部,地図中のアで示した川の名前は？,流路は簡略化して示しています。,,jg-0140
jg-0260,黒潮（日本海流）,くろしお（にほんかいりゅう）,海流,,地図中のアで示した海流の名前は？,矢印は海流の主な流れる向きを表します。,日本海流;にほんかいりゅう;黒潮;くろしお,
jg-0276,東京,とうきょう,都道府県庁所在地,関東,地図中のアで示した都道府県庁所在地は？,●・○は都道府県庁所在地を表します。,,
```

分類の一覧と、まとめ（成績の内訳・範囲のチップ・一覧の見出しの単位。`categories` の値）はコードの表で持つ。並びは表の順。一覧に無い分類は検証で止める。

| まとめ | 含む分類 | 件数 |
|---|---|---|
| 山地・山脈 | 山地・高地、山脈、山脈群 | 29 |
| 山 | 山・火山 | 18 |
| 平野・盆地・台地 | 平野、盆地、台地、高原・台地 | 61 |
| 川・湖 | 河川、湖 | 65 |
| 半島・岬 | 半島、岬 | 25 |
| 島 | 島・諸島 | 29 |
| 海・湾・海流 | 海、湾、海峡、海岸・砂丘、海流、標準時子午線 | 36 |
| 県庁所在地 | 都道府県庁所在地 | 47 |

- GeoPlace の型は `{ id, name, reading, category, regions: string[], question, note: string | null, altNames: string[], similar: string[], level: '中学', role }`。地図の画像の URL は `/geography/<id>.webp` で、型には持たず `geography.ts` の関数で作る。
- 地理データの「正しさ」は、地理学の細分や現地の呼び方ではなく、現代の中学受験で正解とされる名前・読み・別解と、受験の教材で教える地図の概略とする（年表・語彙と同じ絶対の方針）。基準の詳細、列の使い分けと書き方、データを足す手順、確定した個別の判断（黒潮と日本海流の併記の順と別解、都道府県庁所在地の「市」、同じ川の区間名の `similar` など）は `docs/data.md` の 8 章にまとめる。

地図の画像:

- 元の画像（1440×1260 の PNG。問題 ID・問題文・答えの欄・注記・クレジットを含む）と、それを描く定義・スクリプト・根拠資料は `output/` にあり、git に入れない。アプリが配るのは変換後の `public/geography/<id>.webp` だけ。
- 変換は `scripts/geography-images.ts`（手動で実行。`npm run geography:images -- <素材のディレクトリ>`。素材のディレクトリは元の一覧 `questions.csv` と `images/` があるところ）。元の画像のレイアウトは全件で固定なので、地図・位置図・北の矢印だけが入る固定の枠（左 80・上 215・幅 1280・高さ 830）で切り抜き、幅 1000px（高さ 648px）に縮め、WebP（品質 85）で書く。1 枚 約 33 KB、310 枚で約 10 MB。元の画像との対応は元の一覧の行の順で取る（元の一覧の N 行目が `jg-N`。id を元の一覧の順に振っているため）。確認として元の一覧の名称と `name` を比べ、違えば止める。ただし、全角の括弧の前後を入れ替えただけの違い（元の「日本海流（黒潮）」と `name` の「黒潮（日本海流）」）は同じとみなす。元の画像にあった注記は `note` 列に、クレジットは画面の文に移す。
- 幅 1000px は、iPhone 16 Pro（幅 402pt・3 倍）で地図を画面いっぱい（約 335pt）に出すのに要る大きさ。品質 85 とロスレスは 3 倍に拡大しても見分けられず（PSNR 42〜48 dB）、90 より約 15% 軽い。WebP は iOS 14 以降で表示できる（9.4 節）。
- 画像は Service Worker の事前キャッシュに入れ、オフラインでも出題できるようにする（9.2 節）。Workbox が画像ごとにハッシュを持つので、コードだけの更新では画像を再取得しない。
- 出典: 地図は Natural Earth（パブリックドメイン）と国土地理院などの資料をもとに作った概略図。出典と利用条件の一覧は `data/decks/japanese-geography/sources.csv`（`id,title,url,license,usage,checkedOn`）。画面には、出題の画面の一番下に 1 行のクレジット「地図: Natural Earth と国土地理院の資料をもとに作成」を、一覧の一番下に URL 付きの出典の注記を出す（6.10 節・6.12 節）。国土地理院コンテンツ利用規約は出典（URL 付き）と加工した旨の記載を求め、地理院タイルの規約はタイル一覧ページへのリンクを求めるため。

検証（`scripts/build-data.ts` とテストで自動確認。5.2 節と同じ段取り）:

- `id` が全ファイルを通して一意で `jg-` で始まること。`name` が全ファイルを通して一意であること。`id`・`name`・`reading`・`category`・`question` が空でないこと。
- `category` が分類の一覧にあること。`regions` の各値が地方の一覧にあること。`question` が全角 30 字、`note` が全角 50 字以内であること。
- `alt_names` の各値が空でなく、その行の `name`・`reading` と重複しないこと。`similar` の各 id が全ファイルのどこかに存在し、自分自身でないこと。
- 全行について `public/geography/<id>.webp` があること（`build-data.ts` が確かめる。`src/core` はファイルを読まない）。
- 名前 4 択に適格でない行（6.12 節）は検証では止めない（名前入力で出る）。
- CSV の形式は 5.1 節と同じ（UTF-8、改行は LF か CRLF、9 列のヘッダー固定、任意の列も省略しない、カンマと `"` の扱い、セル内の改行は不可）。

## 6. 出題の仕様

6.1〜6.3 節と 6.7 節は年表の教材の出題。語彙の教材は 6.8 節、英単語の教材は 6.11 節、日本地理の教材は 6.12 節。6.4〜6.6 節と、ホームの教材の切り替え（6.9 節）、一覧（6.10 節）は教材に共通で、一覧は種類ごとの差分（5 章の冒頭の表）だけを持つ。

### 6.1 出題対象と適格条件

1. 母集団は `level` が `中学` の出来事（`core.csv` と `pool.csv` の両方。`高校` の行は誤答の候補にのみ使う）。出題設定の「出題する出来事」で「基本の年表のみ」（既定。利用者がまとめた初期データ = `core.csv` の行だけ）か「すべて」（追加データを含む）を選ぶ。復習と成績はこの設定によらず母集団全体を対象にする。
2. 範囲指定を適用する。判定には代表年 `year` だけを使い、`alt_years` は使わない。
   - 全範囲: 絞り込みなし。
   - 年号の範囲: 開始年・終了年のどちらも任意入力で、1〜4 桁の正の整数のみ受け付ける。両端を含む。空の側は開いた範囲。両方空は全範囲と同じ。紀元前の出来事は開始年が空のときだけ含まれる。開始年が終了年より大きいときは理由を表示して開始ボタンを無効にする。
   - 時代: 選んだ時代（複数可）に属する出来事。1 つも選んでいなければ開始ボタンを無効にする。
3. パターンごとの適格条件。
   - 年号入力: `approx` でなく、`year` が正の出来事。
   - 年号 4 択: 年号入力と同じ（6.7 節）。
   - 出来事 4 択: 6.3 節の除外規則を適用した後の誤答候補が 3 件以上ある出来事（データだけで決まるので、出来事ごとに初回だけ計算して覚えておく）。
   - ミックス: 出来事ごとに、適格なパターン（3 つのうちの 1〜3 つ）から 1 問ごとに等確率で選ぶ。どれにも適格でなければ除外する。
4. 問題数は 10・20・全問から選ぶ（既定 10）。適格な出来事が問題数に満たなければ適格な全件を出す。出題順はランダムで、同じセッション内で同じ出来事は 1 回だけ出す。
5. 適格な出来事が 0 件なら開始せず、その旨を表示する。
6. 問題列と各問題の選択肢はセッション開始時に生成して固定する。

### 6.2 パターン A: 年号入力

- 表示: 出来事の文、数字の入力欄（`inputmode="numeric"`、`pattern="[0-9]*"`）、回答ボタン。入力欄の下の左端に、灰色の小さな文字で「わからない」を置く（「回答」から離して、目立たせない）。
- 入力の正規化: 前後の空白を除き、全角数字は半角に直す。1〜4 桁の数字のときだけ回答ボタンを有効にする。先頭の 0 は無視する（`0710` は `710`）。
- 判定: 整数にして、`year` または `alt_years` のいずれかに一致すれば正解。「わからない」は入力が無くても押せて、不正解として記録する（復習の対象になる）。
- 表示: 判定の帯（6.4 節の 3）に「正解」「不正解」「わからない」のいずれかと、正解の年（`alt_years` があれば併記）を出す。正解のときも年を出す。その後「次へ」。1 問につき回答は 1 回だけ受け付ける（判定後は入力とボタンを無効にし、「わからない」は消す）。

### 6.3 パターン B: 出来事 4 択

0.1 系では「4 択」と呼んでいた。出来事を見せて年号を選ぶ年号 4 択は 6.7 節。

- 表示: 5.3 節の規則で表示した年（例「1185年の出来事は？」「3世紀の出来事は？」）、出来事 4 つのボタン。
- 正解: 出題した出来事。
- 誤答の候補の除外規則（`core.csv`・`pool.csv` の全出来事から、次に当たるものを除く）:
  1. 出題した出来事自身。
  2. `year` または `alt_years` のいずれかが出題年と一致するもの。
  3. 出題した出来事か候補のどちらかが `approx` の場合、`year` の差が 50 年以内のもの（「3 世紀」と表示した問題に 239 年の出来事が混ざらないようにする）。
- 誤答 3 件の選び方: 候補のうち `year` が出題年の前後 100 年以内のものから 3 件をランダムに選ぶ。3 件に満たなければ、同じ時代の候補、さらに全候補の順で補う（選択済みのものは除く）。
- 4 つの並びはシャッフルする。判定後は正解の選択肢を強調表示し、不正解なら選んだものも示す。1 問につき回答は 1 回だけ受け付ける。
- 選択肢の下の左端に、年号入力と同じ「わからない」を置く。押すと不正解として記録し、判定の帯に「わからない」を出して正解の選択肢を強調する（選んだ答えの表示は無い）。当てずっぽうで正解して復習から外れるのを防ぐ。

### 6.4 セッションの流れ

1. ホーム → 出題設定（出題する項目・パターン・問題数・範囲）→ 開始。設定は「開始」を押した時点で、その教材の出題設定（`meta` の `settings:<教材の id>`。5.4 節）に保存し、次回の初期値にする（「戻る」で抜けたときは保存しない）。保存した設定が無いときの初期値は、年表が「基本の年表のみ・年号入力・10 問・全範囲」、語彙が 6.8 節の 4、英単語が 6.11 節の 4。
2. 開始時に `sessions` にレコードを作る（`endedAt` は `null`）。
3. 1 問ごとに回答 → 保存（5.4 節のトランザクション）→ 判定表示 → 次へ。判定は画面の下に固定する帯（判定の帯）に、正解・不正解・わからないと「次へ」を並べて出す。画面上部には「3 / 10」の進捗と、問題ごとの区切り（答えた問題は判定の色、今の問題は主な操作の色）を出す。問題数が 20 を超えるときは区切りにせず、回答済みの割合を 1 本の帯で示す。「次へ」で次の問題に進むときは画面の先頭へ戻す（縦に送る問題が続いても、次の問題文が隠れたまま始まらないように。1.3 で追加。教材によらず共通）。
4. 最後の問題も同じように判定を表示する。最後の問題の回答を保存するトランザクションで `endedAt` も記録し、「次へ」の代わりに「結果を見る」を表示する。押すとまとめ画面へ進む。
5. 途中で「終了」を押すと確認の後に `endedAt` を記録してまとめ画面へ進む（回答済みの分は成績に残る）。
6. まとめ画面: 正答数 / 回答済み数（予定の問題数とは区別する。正答の割合を輪のグラフで示す）、問題数が 20 以下なら 1 問ずつの判定の区切り、予定の問題数（途中で終了したときはその旨）、間違えた出来事の一覧（出来事と正解の年。「わからない」を含む）、ホームへ戻る。間違えた出来事の行を押すと一覧（6.10 節）のその出来事に移り、一覧の「結果に戻る」（または上部の「戻る」）でこの画面に戻る（1.2。語彙も同じ）。
7. 起動時に `endedAt` が `null` のセッションがあれば、`answered` が 0 のものは削除し、それ以外は中断として扱う（再開はしない。履歴には「中断」と表示する）。

### 6.5 ホーム画面からの起動の確認

- iOS で、ホーム画面から起動していないとき（`navigator.standalone` が true でない）は、ホーム画面の上部に「Safari の共有メニューから『ホーム画面に追加』して使ってください」という帯を出す。帯はその起動の間だけ閉じられる。
- 理由: Safari のタブで使い続けると、7 日間そのサイトに触れないと保存データが消える規則があるため。ホーム画面に追加した Web アプリはこの規則の影響を実質受けない。

### 6.6 アプリの更新

- `vite-plugin-pwa` の `registerType` は `prompt`。新しい版を検知したらホーム画面にだけ「新しいバージョンがあります」の帯と「更新」ボタンを出す。押すと新しい Service Worker を有効にして再読み込みする。
- 新しい版を探すのは、アプリを起動したとき（ページを読み込んだとき）と、ホーム画面の「アプリを更新」を押したとき。
- 押さなくても、アプリを完全に閉じて次に起動したときに新しい版になる。学習中に勝手に再読み込みはしない。同じブラウザの別のタブが更新を適用しても、この画面は再読み込みせず、「更新」を押したときに再読み込みする。
- ホーム画面の下部にアプリの版（`package.json` の `version`）を表示する。
- 「アプリを更新」（0.1.1 から）: ホーム画面の下部、版の表示の横に置く。押すと通信して新しい版を探し、結果をボタンの下に出す。確認と読み込みの間はボタンを押せなくする。
  - 新しい版があれば、読み込みを待ってから、そのまま新しい版に切り替える（帯の「更新」を押したときと同じ動き）。確認の間は「確認しています」、読み込みの間は「新しい版を読み込んでいます」と出す。
  - 新しい版を読み込み済みで帯が出ているときは、通信せずにすぐ切り替える。
  - 新しい版が無ければ「最新の版です」と出す。
  - 通信できないとき、読み込みに失敗したとき、Service Worker が使えないときは「確認できませんでした。通信できる場所でもう一度押してください」と出す。
  - ボタンはホーム画面にしか無いので、学習の途中で切り替わることはない。

- 読み込みの進み具合（1.4.1 から）: 新しい版の読み込み（Service Worker の install。事前キャッシュの取得）の間、ホームに進み具合を横棒と百分率（「42%」）で出す。1.5 で地図の画像 310 枚（約 10 MB）が事前キャッシュに加わり、読み込みに数十秒かかることがあるため。
  - 仕組み: Service Worker は自前の `src/sw.ts`（`injectManifest`。9.2 節）。install で、事前キャッシュの一覧のうちまだキャッシュに無いファイルの数を数え（Workbox の `PrecacheController` のキャッシュキーで照合する）、1 ファイル取り込むごとに、同じ配信元の全ウィンドウ（制御下に無いものも含む。`clients.matchAll({ includeUncontrolled: true, type: 'window' })`）へ `{ type: 'PRECACHE_PROGRESS', done, total }` を送る。取り込みが終わったら `done = total` を送る。単位はファイル数で、バイト数ではない（地図の画像が容量の大半を占めるので、ほぼ比例する）。
  - 画面側（`src/pwa/update.ts`）は `navigator.serviceWorker` の `message` を起動時から聞き、最新の `done / total` を持つ。`useAppUpdate` が `progress`（`{ done, total } | null`）を返す。
  - 表示する場面は 3 つで、同じ部品（文、横棒、百分率）を使う。(a) 起動時に新しい版が見つかって取り込みが始まったとき: ホーム上部の帯に「新しい版を読み込んでいます」と横棒。取り込みが終わると今の「新しいバージョンがあります［更新］」の帯に変わる。(b) 「アプリを更新」を押したとき: ボタンの下の「新しい版を読み込んでいます」の文に横棒を添える（帯は出さない）。(c) 初めて開いたとき（まだ制御下に無いとき）: 上部の帯に「オフラインで使えるように準備しています」と横棒。終わったら帯を消す。
  - 進捗の知らせが届かないとき（1.4.1 より前の版の Service Worker、Service Worker が使えない環境）は、今までどおり文だけを出す。横棒は `total` が 1 以上で `done < total` の間だけ出す。
  - 取り込みが失敗したとき: 進捗は取り込み中の worker（`registration.installing`）と対応づけ、その worker が `redundant` になったら（取得や保存の失敗で install が中断したとき）進捗を消す。(a) と (c) の帯は消すだけにする（起動時の自動の取り込みは、次に開いたときにブラウザがやり直す）。(b) は既存の判定どおり「確認できませんでした。通信できる場所でもう一度押してください」を出す。新しい取り込みが始まったら（`updatefound` で新しい worker を検知したら）`done / total` を初期化し、Service Worker からの最初の知らせ（`done = 0`）で表示を始める。
  - 進捗は「今、端末に入っている版」の画面が出すものなので、1.4.1 を先に配る。1.4.1 より前の版からの更新では横棒は出ない（10 章）。
  - 学習中（ホーム以外）は出さない。帯もボタンもホームにしか無く、学習中に勝手に切り替えない方針は変わらない。

- 「記録の管理」（1.3.2 から）: ホーム画面の下部、「アプリを更新」の右に同じ見た目の文字のボタンを置く（狭い画面では行を折り返す）。押すと記録の管理の画面（5.6 節）を開く。学習の記録の準備ができていない間（読み込み中・開けなかったとき）は押せない。

### 6.7 パターン C: 年号 4 択

- 表示: 出来事の文、「何年の出来事？」、年号の選択肢 4 つ（例「1575年」）。選択肢は 2 列 2 段に、小さい順に並べる。年号 4 択に出るのは `approx` でなく `year` が正の出来事なので、年は「○○年」の形になる。
- 正解: `year`。`alt_years` の年は選択肢に出さない（別解の年が誤答として並ぶと、正しい答えを不正解にしてしまうため）。
- 誤答の年 3 つの選び方:
  1. 候補は、`year` の前後 1〜10 年の 20 個から、0 以下の年、今年（端末の現在の暦年）より後の年、`alt_years` の年を除いたもの。端末の時計が出来事の年より前にずれているときは、出来事の年を今年とみなす（選択肢を作れずに出題が止まらないように）。
  2. 正解より小さい誤答の数 k（0〜3）を先に決める。正解より小さい候補が k 個以上、大きい候補が 3 − k 個以上ある k の中から、等確率で選ぶ。
  3. 正解より小さい候補から k 個、大きい候補から 3 − k 個を、重複なくランダムに選ぶ。
  - 理由: 20 個から 3 つを一様に選ぶと、小さい順に並べたときに正解が 2 番目か 3 番目に来る割合が約 8 割になり、真ん中を選ぶだけで当たりやすくなる。k を先に決めると、正解が 1〜4 番目のどこにも同じ割合で来る（候補が片側に足りない年を除く）。
- 判定: 選んだ年が `year` と一致すれば正解。判定後は、出来事 4 択と同じく正解の選択肢を強調表示し、不正解なら選んだものも示す。判定の帯には「正解」「不正解」「わからない」のいずれかと、正解の年（`alt_years` があれば併記。年号入力と同じ表示）を出す。1 問につき回答は 1 回だけ受け付ける。
- 選択肢の下の左端に「わからない」を置く（6.3 節と同じ動き）。
- 選択肢はセッション開始時に生成して固定する（6.1 節の 6）。今年は、注入できる現在時刻から求める（3 章）。

### 6.8 語彙の出題（意味 4 択・言葉 4 択）

教材の種類「言葉と意味」の出題（1.1）。6.1 節の 4〜6（問題数、出題順、選択肢の固定）、6.4 節（セッションの流れ）、「わからない」の動き（6.3 節）は年表と同じ。

出題対象と適格条件:

1. 母集団は `level` が `中学` の言葉（`core.csv` と `pool.csv` の両方。`高校` の行は誤答の候補にのみ使う）。出題設定の「出題する言葉」で「基本の語彙のみ」（既定。`core.csv` の行だけ）か「すべて」（追加データを含む）を選ぶ。復習と成績はこの設定によらず母集団全体を対象にする。
2. 範囲の指定は「全範囲」「種類（複数選択可）」の 2 通り。種類のチップには、母集団に言葉がある種類だけを一覧の順に出す。1 つも選んでいなければ開始ボタンを無効にする。保存の形は `{ kind: 'all' }` か `{ kind: 'categories', categories: string[] }`（選んだ種類を一覧の順に並べる）。
3. 適格条件は、意味 4 択と言葉 4 択のどちらも「除外規則を適用した後の誤答の候補が 3 件以上ある言葉」。データだけで決まるので、言葉ごとに初回だけ計算して覚えておく（出来事 4 択と同じ）。ミックスは、2 つのパターンから 1 問ごとに等確率で選ぶ。
4. 保存した設定が無いときの初期値は「基本の語彙のみ・意味 4 択・10 問・全範囲」。

誤答の候補の除外規則（`core.csv`・`pool.csv` の全言葉から、次に当たるものを除く）:

1. 出題した言葉自身。
2. 種類が出題した言葉と違うもの（慣用句の問題にことわざを混ぜない）。
3. 出題した言葉か候補のどちらかの `similar` に、相手の id があるもの（両方向）。

誤答 3 件の選び方: 候補から重複なく一様にランダムに選ぶ。年表の「前後 100 年」のような優先の段階は設けない。使ってみて易しすぎれば、同じ字（体の部分など）を含む言葉を優先する段階を足す（`docs/BACKLOG.md` の候補）。

パターン D「意味 4 択」（`meaningChoice`）:

- 表示: 「どんな意味？」と言葉のカード（言葉を大きく出す）、意味の選択肢 4 つ（ボタン）。選択肢の並びはシャッフルする。
- 正解: 出題した言葉の `meaning`。誤答: 選んだ 3 件の言葉の `meaning`。
- 判定後: 正解の選択肢を強調表示し、不正解なら選んだものも示す（出来事 4 択と同じ札）。判定の帯には「正解」「不正解」「わからない」のいずれかと、`reading` があれば「読み ○○」を出す。1 問につき回答は 1 回だけ受け付ける。
- 選択肢の下の左端に「わからない」を置く（6.3 節と同じ動き）。

パターン E「言葉 4 択」（`wordChoice`）:

- 表示: 「この意味の慣用句は？」（種類の名前を入れる）と意味のカード、言葉の選択肢 4 つ（ボタン）。並びはシャッフルする。
- 正解: 出題した言葉の `word`。誤答: 選んだ 3 件の言葉の `word`。
- 判定後と「わからない」: 意味 4 択と同じ。帯の読みは正解の言葉のもの。

まとめ画面（6.4 節の 6）の「間違えた項目」の一覧は、語彙では言葉・読み（ある場合）・意味の順に出す。

- 意味の文は全角 30 字までなので、幅 375px では選択肢が 2 行になることがある。年表の題名（上限 36 字）と同じ扱いで、選択肢 4 つと判定の帯が 1 画面に収まる（`docs/visual-design.md` の 3 章）。
- 画面は既存の部品（問題のカード、4 択の札、判定の帯、切り替えボタン、チップ）の組み合わせで作り、デザインの見直しは回さない。

### 6.9 教材の切り替え（ホーム）

1.1 で足し、1.1.1 でホームの構成を整えた。

- ホームの教材のカードに、上から教材の切り替えボタン（日本史年表 / 語彙 / 英単語 / 日本地理。1.5 から 4 つ。教材が 4 つのときは 2 列 2 段（上の段が日本史年表・語彙、下の段が英単語・日本地理）に並べる）、教材名、件数、「出題」、区切り線、「一覧」（年表は「年表を覚える」、語彙は「言葉を覚える」、英単語は「英単語を覚える」、日本地理は「地図で覚える」。6.10 節。1.2 で追加）、「復習」、「成績」の行を置く。切り替えで変わるものを 1 枚のカードにまとめる。教材が 1 つのときは切り替えを出さず、カードは教材名から始まる。
- 選んだ教材は `meta.lastDeck` に保存し、次回の初期値にする。保存が無いときと、無い教材を指しているときは最初の教材（日本史年表）。
- カードの件数（出題できる項目の件数と基本の件数。「基本のみ / すべて」の切り替えが無い教材（英単語）では基本の件数を出さない）、「出題」、「一覧」、「復習」の件数の札、「成績」は選んだ教材のもの。全教材で共通の連続学習日数（`studyDays` は共通）は、カードの外のロゴの右に出す。全教材の記録をまとめて扱う「記録の管理」も、カードの外のホームの下部に置く（1.3.2 から。6.6 節）。学習の記録の読み込み中の文と、開けなかったときのエラーも、カードの外（ロゴの行とカードの間）に置く。
- 出題設定・一覧・復習・成績の画面は選んだ教材で開き、見出しの下に教材の名前を出す。出題設定の内容は教材の種類で変わる（年表は 6.1 節、語彙は 6.8 節、英単語は 6.11 節、日本地理は 6.12 節）。
- 出題と結果の画面の形は教材で変えない（問題の部品だけが教材の種類で変わる）。

### 6.10 一覧（年表を覚える・言葉を覚える）

1.2 で足す。選んだ教材の母集団を眺める画面で、年や意味を隠して暗記カードとしても使う。出題の前に時代や言葉をまとめて覚える受け皿と、間違えた出来事を前後の流れの中で見直す手段になる。画面の形は教材の種類で変えず、名前・見出し・行の表示・隠すもの・並び順だけを種類ごとの差分（5 章の冒頭の表。`decks.ts` の `KindRules`）に持つ。画面は既存の部品（切り替えボタン、チップ、一覧のカード、札）の組み合わせで作り、デザインの見直しは回さない。

入口と名前:

- ホームの教材のカードの行に「一覧」を足す（6.9 節。「復習」「成績」の上）。行の名前と画面の見出しは教材の種類で決まり、年表は「年表を覚える」、語彙は「言葉を覚える」、英単語は「英単語を覚える」、日本地理は「地図で覚える」（1.5）。語彙に種類を足しても名前は変えない（種類の見出しで慣用句などが分かる）。
- 結果画面の「間違えた項目」の行を押しても開く（6.4 節の 6。下の「結果画面から開いたとき」）。

対象と並び:

- 対象は選んだ教材の母集団（`level` が `中学` の項目。`core.csv` と `pool.csv` の両方）。`高校` の行は出さない。
- 年表は時代（確定した時代。5.3 節）ごとの見出しの下に、`year` の昇順、同じ年は id 順で並べる。見出しは時代区分表の順。年の表示は 5.3 節の規則で、別解があれば併記する（結果画面と同じ `formatAnswerYears`）。
- 語彙は種類ごとの見出しの下に、読みの五十音順で並べる。読み（無ければ言葉そのもの。読みが無いのはかな書きの言葉だけ）を日本語の照合順（`Intl.Collator('ja')`。濁点・半濁点・小書きの違いを辞書と同じ順に扱う。コードポイントの順では「顔から火が出る」が「顔が広い」より先になる）で比べ、同じなら id 順。見出しは種類の一覧の順。
- 英単語はレッスンごとの見出し（「STAGE2 Lesson 4」。本の順・番号の順）の下に、id の順（一覧に入れた順）で並べる（1.3）。
- 日本地理は分類のまとめ（5.9 節の表。8 つ）ごとの見出しの下に、id の順（元の一覧の順。分類ごとに北から南へ並ぶ）で並べる（1.5）。
- 本文の見出しは、絞り込んだ後に項目がある時代（種類）だけ出し、絞り込んだ後の件数を名前のすぐ右に添える（チップの候補は母集団を基準にする）。全体が 0 件なら見出しを出さず「ありません」だけを出す。見出しはスクロールしても画面の上に留まる（`position: sticky`。iOS 15 で使える）。
- 1.3.2: 各見出しの帯の右端に、上向きの山形と「上へ」を置く。「戻る」と同じ色・太さ・押したときの色で、文字は見出しと同じ 15px。件数は名前との間を 8px 空け、薄い文字・通常の太さで出す。帯の高さは従来の 45px、ボタンの押せる高さは 44px 以上とし、幅 375px でも名前・件数・ボタンが重ならず、横スクロールを出さない。
- 「上へ」は、上部の件数の行の下端が画面の上端より上にある間だけ、すべての見出しに出す（結果画面から該当の行へ送ったときも同じ）。件数の行が少しでも見えている間は、ボタンの場所を空けたまま隠し、押せず、読み上げにも Tab の移動先にも出さない。出し入れのアニメーションは付けない。
- 押すと `window.scrollTo(0, 0)` でアニメーションなしに画面の一番上へ戻す。絞り込み・「隠す」・出した行の状態は保ち、結果画面から開いたときの行の強調と下の「結果に戻る」の帯も保つ。

絞り込み（画面の上部）:

- 「表示する出来事」（語彙は「表示する言葉」、日本地理は「表示する地名」）: 基本の年表のみ / すべて。出題設定と同じ部品と意味（`core.csv` の行だけか、追加データを含むか）。初期値は、その教材の出題設定に保存した「出題する項目」（保存が無ければ基本のみ）。「基本のみ / すべて」の切り替えが無い教材（英単語）では出さず、全行を対象にする。
- 時代（語彙は種類、英単語はレッスン、日本地理は分類のまとめ）のチップ: 日本地理は 2 列、ほかの教材は 3 列。出題設定の部品で、母集団に項目がある時代（種類・レッスン・まとめ）だけ出す。英単語は本ごとの見出しの下に「Lesson 4」で並べる（6.11 節の 2 と同じ部品）。複数選べ、何も選んでいなければ全部を出す（出題設定と違い、0 件で止めない）。入口（ホーム・結果画面）を問わず、初めは未選択。
- 件数の行に、表示中の範囲と絞り込んだ後の件数を出す（何も選んでいなければ「すべての時代 371 件」、選んでいれば「昭和・平成 91 件」。語彙は「すべての種類」、英単語は「すべてのレッスン」と、選んだレッスンを 6.11 節の形で本ごとにまとめたもの、日本地理は「すべての分類」と、選んだまとめを 6.12 節の形で「、」でつないだもの）。未選択が全部を出す意味であることは、説明の文ではなくこの行で伝える。0 件なら「ありません」。件数は範囲の文字列と別の要素にして間を空ける（「Lesson 5 10 件」のように数字が続いて読みにくくならないように）。
- 絞り込み・「隠す」・出した行の状態は保存せず、画面を開くたびに初期値にする（結果画面から開いたときは下の初期値）。一覧は出題設定を書き換えない。

隠す（暗記カード）:

- 「隠す」の切り替えボタン（3 つ）を絞り込みの下に置く。年表は「隠さない / 年 / 出来事」、語彙は「隠さない / 意味 / 言葉」、英単語は「隠さない / 意味 / 英単語」、日本地理は「隠さない / 名前 / 地図」。初期値は「隠さない」。
- 隠すと、全行のその部分が「？」の灰色の札になる。行を押すとその行だけ出て、もう一度押すと隠れる。「隠す」の設定を変えると、出した行はすべて隠し直す。
- 語彙で「言葉」を隠すときは読みも隠す（読みで言葉が分かるため）。「意味」を隠すときは言葉と読みを出す。英単語で「意味」を隠すときは品詞の略記も隠す（2 段目を丸ごと札にする）。日本地理で「名前」を隠すときは読みも隠し、地図から名前を思い出す暗記カードになる。「地図」を隠すと 2 段目（地図）が「？」の札になり、名前だけの目次として使える。行を押すとその行の地図を出す（画像はそのとき読み込む）。
- 隠した文字は画面に置かない（DOM に出さない）。

行の表示:

- 年表: 左に年（5 文字分の列。`5世紀ごろ` などの長い表示は列の中で折り返す）、右に題名（折り返す。中央値 25 字で 2 行、最長 33 字で 3 行）。
- 語彙: 1 段目に言葉と読み（読みは小さく薄く。読みが無ければ言葉だけ）、2 段目に意味。
- 英単語: 1 段目に英単語、2 段目に品詞付きの意味（「(名) 場所、地点」。5.8 節）。読みは無い。
- 日本地理: 1 段目に名前と読み、2 段目に地図の画像（幅いっぱい、比率 1000:648。`loading="lazy"` で画面に近づいた行から読み込む）。注記は出さない（出題の画面だけ）。一覧の一番下（最後の見出しのカードの下）に出典の注記を 1 つ出す: 「地図は、Natural Earth（パブリックドメイン）と、国土地理院ウェブサイト・地理院タイルなどの資料をもとに、このアプリ用に独自に作成した概略図です。」に、国土地理院ウェブサイト（https://www.gsi.go.jp/）、地理院タイル一覧（https://maps.gsi.go.jp/development/ichiran.html）、Natural Earth（https://www.naturalearthdata.com/）へのリンクを添える（出題の画面の出典の 1 行と同じ 12px の補助の文字。リンクは別のタブで開く。リンクの押せる範囲は文字の行の高さのままにし、44px に広げない。出典を示すためのリンクで、押すように促すものではないため。押すときは画面を拡大して押せる）。
- 復習の候補（7 章の数え方。パターンを問わず 1 つでも候補なら）に入っている行には「復習」の札を添える。ホームの「復習」の件数と同じ計算で、絞り込みは設けない。
- 行は押せる部品（高さ 44px 以上）。

結果画面から開いたとき:

- 開く前に、その項目が一覧に入るように初期値を決める。項目が追加データ（`role` が `pool`）なら「すべて」、そうでなければ上の初期値。時代（種類）のチップは選ばない。「隠す」は「隠さない」。
- 開いたらその行が画面の中央に来るように送り（上に留まる見出しに隠れないように）、強調して示す（主な操作の薄い色の背景）。強調は画面を離れるまで続ける。
- 下に固定する帯に「結果に戻る」を置く（結果画面の「ホームへ」と同じ部品）。一覧の途中へ移った直後でも、上部の「戻る」まで戻らずに結果画面へ戻れる。上部の「戻る」も結果画面に戻る。戻った結果画面は、内容と、一覧を開く前の閲覧位置を保つ（位置はメモリ上だけで持つ。間違えた項目を順に見直すときに探し直さなくてよいように）。ホームから開いたときは帯を出さず、「戻る」はホームへ。画面の状態には一覧の戻り先を持つ。

実装の注意:

- 画面を切り替えたときに先頭へ戻す処理（`App.tsx`）は、子の画面の effect より後に動く。該当の行まで送る処理はその後に行う（App が一覧では先頭へ戻さない、または一覧が次の描画の後に送る）。結果画面へ戻るときも先頭へ戻さず、保存した閲覧位置へ送る。
- 見出しはカードの外に置き、時代（種類）ごとにカードを分ける（成績の節の見出しと同じ形）。既存の一覧のカード（`.list-card`）は `overflow: hidden` を持つので、その中に置いた見出しは画面に留まらない。
- 371 行を折りたたまずに 1 画面に出す。成績の「出来事別」が同じ件数を出していて iPhone 7 で確かめ済みのため。実機で重ければ時代ごとの折りたたみを足す。
- 日本地理の一覧は、基本の地名だけでも地図が 142 枚、「すべて」で 310 枚並ぶ。`loading="lazy"` と `decoding="async"` で画面に近い行から読み込み、`width`・`height` を付けて行の高さを先に確保する（送り位置がずれないように。結果画面から該当の行へ送る処理にも効く）。iPhone 7 で送りの重さを確かめる。
- 保存（IndexedDB・書き出しの形式）の変更は無い。

### 6.11 英単語の出題（意味 4 択・英単語 4 択・つづり入力）

教材の種類「英単語」の出題（1.3。つづり入力は 1.4）。6.1 節の 4〜6（問題数、出題順、選択肢の固定）、6.4 節（セッションの流れ）、「わからない」の動き（6.3 節）は年表と同じ。

出題対象と適格条件:

1. 母集団は `core.csv` の全行（`高校` の行と追加データは無い）。出題設定に「出題する英単語」の切り替えは出さない。復習と成績も母集団全体を対象にする。
2. 範囲の指定は「全範囲」「レッスン（複数選択可）」の 2 通り。レッスンのチップは、母集団にあるレッスンを本ごとの見出し（STAGE1 / STAGE2 / STAGE3。母集団にある本だけ）の下に「Lesson 4」の形で、本の順・番号の順に出す（小カテゴリの名前がどの本でも「Lesson 番号」なので、本の見出しで区別する）。1 つも選んでいなければ開始ボタンを無効にする。保存の形は `{ kind: 'all' }` か `{ kind: 'categories', categories: string[] }`（値はレッスンの名前「STAGE2 Lesson 4」。本の順・番号の順に並べる）。読み出すときに今のデータに無いレッスンは除き、残りが空なら全範囲に戻す（語彙の種類と同じ）。
3. 適格条件は、意味 4 択が「除外規則を適用した後に、異なる `meaning` の候補が 3 件以上ある英単語」、英単語 4 択が「除外規則を適用した後に、異なる `word` の候補が 3 件以上ある英単語」。つづり入力は「`word` に穴（`...` または `…`）を含まない英単語」。どれもデータだけで決まるので、英単語ごとに初回だけ計算して覚えておく。ミックスは、その英単語に適格なパターンから 1 問ごとに等確率で選ぶ（1.3 は 2 つ、1.4 からは 3 つ）。
4. 保存した設定が無いときの初期値は「意味 4 択・10 問・全範囲」。

範囲の表示（履歴と、一覧の件数の行）: 選んだレッスンを本ごとにまとめ、本の順・番号の順で「STAGE2 Lesson 4・5、STAGE3 Lesson 1」の形にする。全範囲は「全範囲」。

同じ答えの集まり: 行 X の集まりは、X から「`meaning` が同じ」と「どちらかの `similar` に相手の id がある（両方向）」の関係をたどって届く全行（X を含む）。liberty と freedom は同じ意味でつながり、somebody と anybody は `similar` でつながり、someone は somebody と同じ意味なので anybody にもつながる。集まりはデータだけで決まるので、行ごとに初回だけ計算して覚えておく。意味 4 択の除外と英単語 4 択の除外は、この集まりで決める（同じ問題文なら、出題元の行がどれでも同じ選択肢の条件になる）。つづり入力の正解は、この集まりではなくカードの文で決める（パターン H）。集まりは `similar` をたどって広がるので、誤答から外す範囲には使えるが、正解の範囲に使うと広がりすぎる（「誰か」の集まりには anybody と、anybody の `similar` の nobody も入る）。

`word` の同一性（同じ `word` の判定、表示が同じ候補のまとめ、検証の一意性、つづり入力の判定）は、1 つの正規化で比べる: 前後の空白を除き、連続する空白は 1 つにする。全角の英数字と記号は半角にする。大文字と小文字を区別しない。アポストロフィの「’」は「'」にする。末尾の「.」「?」「!」は除く。表示は原文のまま使う（4 択で表記違いの行を誤答に出せるのに、つづり入力では打てば正解になる、という食い違いを無くすため）。

誤答の候補の除外規則（`core.csv` の全行から、次に当たるものを除く）:

1. 出題した英単語自身。
2. 意味 4 択: 出題した英単語と同じ `word` を持つ各行（自分を含む。別のレッスンに同じ英単語が別の意味で載っているとき）の集まりに入る行の `meaning` を持つもの（その英単語の正しい意味や、正解と同じとみなす意味を誤答に出さない）。
3. 英単語 4 択: 出題した英単語の集まりに入る行の `word` を持つもの（同じ意味の別の英単語と、別のレッスンの同じ英単語を誤答に出さない）。

残った候補のうち、表示する文字（意味 4 択は `meaning`、英単語 4 択は `word`）が同じものは 1 件とみなす（「誰か」が 2 つ並ばないように）。

誤答 3 件の選び方: 候補のうち `pos` が出題した英単語と同じもの（空どうしも同じとみなす。「名詞・形容詞」は文字列として一致するもの。表示が同じ行をまとめた候補は、そのどれか 1 行の品詞が同じなら同じとみなす）からランダムに選び、足りなければ全候補から補う（選択済みのものは除く。年表の段階と同じ形）。品詞をそろえるのは、「城 / ～を続ける / 十分な / 誰か」のように品詞だけで正解が分かる問題を避けるため。レッスンや本での優先は設けない（誤答は登録済みの全レッスンから出る）。

パターン F「意味 4 択」（`englishMeaningChoice`）:

- 表示: 「どんな意味？」と英単語のカード（語彙の言葉のカードと同じ部品で、英単語を大きく出す）、意味の選択肢 4 つ（ボタン。品詞は付けない）。並びはシャッフルする。
- 正解: 出題した英単語の `meaning`。誤答: 選んだ 3 件の `meaning`。
- 判定後と「わからない」: 語彙の意味 4 択と同じ（正解の選択肢を強調し、不正解なら選んだものも示す）。判定の帯の補足は出さない（読みが無い）。

パターン G「英単語 4 択」（`englishWordChoice`）:

- 表示: 判定の帯に「正解」「不正解」「わからない」のいずれかと、正解のつづり（判定で正解とする `word` を、正規化した形が同じものは 1 件にまとめて（表記は id の小さい行の原文）、「 / 」でつないで「liberty / freedom」のように id の順に並べる。別のレッスンに同じ英単語が再び載っても重複して出ない）を「正解のつづり liberty / freedom」の形で出す。正解のときも出す。1 問につき回答は 1 回だけ受け付ける（判定後は入力とボタンを無効にし、「わからない」は消す）。

## 7. 復習モード

- 成績は（項目, パターン）の組ごとに `eventStats` に集計されている（5.4 節）。
- 復習は教材ごとに行う。ホームの「復習」の件数の札と復習の画面の件数も、選んだ教材で数える（6.9 節）。
- 候補 = 選んだ教材の母集団（年表は 6.1 節の 1、語彙は 6.8 節の 1）に存在し、記録されたパターン（その教材のパターンのいずれか）に今も適格で、次のいずれかを満たす（項目, パターン）の組。
  1. 直近 14 日以内に不正解がある。
  2. 最後の回答が不正解である。
  3. 回答数が 2 回以上で正答率が 60% 未満である。
- 上の 1〜3 のどれかを満たしていても、次の 2 つをどちらも満たす組は候補から外す（1.1.1 で追加）。
  - (a) 最後に間違えた後に、続けて 2 回以上正解している（`eventStats.consecutiveCorrect`）。
  - (b) 最後の回答の暦日が、最後に間違えた回答の暦日より後である。
- 「わからない」で答えを見た直後や、復習を続けて開いたときの当日中の正解は、覚えたとは限らないため、間違えた日のうちは外さない。月曜に間違え、月曜に 1 回、火曜に 1 回正解すれば火曜に外れる。月曜のうちに 2 回正解した場合は残り、火曜にもう 1 回正解すると外れる。1 日 1 回復習する使い方なら、外れる時期は「続けて 2 回正解したら外す」と同じになる。
- 続けた正解の回数は、通常の出題・復習を問わず（項目, パターン）の組ごとに数える。意味 4 択で間違えた言葉は意味 4 択の正解だけを数え、言葉 4 択の正解は数えない。「わからない」も不正解なので 0 に戻る。外れた後にまた間違えると 0 に戻り、上の 1・2 で候補に戻る。
- 重み付け: 最後に間違えた日からの経過日数が 3 日以内なら 3、7 日以内なら 2、それ以外は 1。重み付きで重複なく抽選する。候補と重みはセッション開始時に確定する。
- 出題パターンは間違えたパターンをそのまま使う。複数のパターンで間違えていればそれぞれが候補になり、同じ項目がパターンごとに 1 問ずつ、年表では最大 3 問、語彙では最大 2 問、英単語では 1.3 で最大 2 問・1.4 から最大 3 問、日本地理では最大 2 問出ることがある（許容する）。4 択の選択肢は、復習のセッションを始めるときに作り直す。
- 復習の設定は問題数だけ（範囲指定とパターン選択は設けない）。問題数は保存せず、毎回 10 から選ぶ。候補が 0 件なら「復習する問題はありません」と表示して開始できなくする。
- 復習の画面の説明は「最近間違えた問題や、正答率の低い問題を出します。続けて 2 回正解すると外れます。ただし、間違えた日のうちは外れません。」とする。
- ホーム画面の「復習」の行に、候補の件数を出す（この章の数え方。0 件なら出さない）。
- 復習は出題設定の「出題する項目」によらず、母集団全体（追加データの中学の行を含む）から候補を選ぶ。
- 復習モードの回答も通常と同じく成績に記録する。

日付の数え方（復習と連続学習日数で共通）:

- 時刻は UTC で保存し、学習日と経過日数は端末の現在のタイムゾーンでの暦日の差で求める。3・7・14 日の境界は含む（経過 14 日は「14 日以内」）。
- 候補から外す条件 (b) の暦日の後先も、端末の現在のタイムゾーンの同じ暦（`src/core/date.ts` の注入できる `DateKeyFn`）で数える。
- 「直近 14 日以内に不正解がある」は、`eventStats.lastWrongAt` が端末の現在のタイムゾーンで 14 日前の 0 時以降かどうかで判定する（不正解の記録がなければ該当しない）。`attempts` は読まない。

## 8. 成績画面

成績はホームで選んだ教材のもの（6.9 節）。対象は出題設定の「出題する項目」によらず、その教材の母集団全体。画面の上部の切り替え（全体 / 項目別 / 履歴）で、出す区分を選ぶ。初めは全体。「項目別」の表示名は教材で変わる（年表は「出来事別」、語彙は「言葉別」、英単語は「英単語別」、日本地理は「地名別」）。

1. 全体: 上から次の順に並べる。
   1. 総回答数、正答率（どちらも選んだ教材の分）、連続学習日数（`meta.studyDays` を使い、今日に回答があれば今日、なければ昨日を起点に、連続した日数を数える。どちらにも無ければ 0。全教材で共通）。連続学習日数はホーム画面にも出す。
   2. まとめる単位ごとの成績: 年表は時代別（時代区分表の順）、語彙は種類別（種類の一覧の順）、英単語はレッスン別（「STAGE2 Lesson 4」。本の順・番号の順）、日本地理は分類別（5.9 節のまとめ 8 つ。表の順）。単位ごとの正答率を横棒（CSS）で表示し、回答数も併記する。母集団に項目がある単位だけを出す。
2. 項目別: 年表は出来事・正答率・回答数・最終回答日、語彙は言葉・読み（ある場合）・種類・正答率・回答数・最終回答日、英単語は英単語・品詞付きの意味・レッスン・正答率・回答数・最終回答日、日本地理は名前・読み・「分類 · 地方」・正答率・回答数・最終回答日の一覧。既定は正答率の低い順。回答数順（多い順）と最終回答日順（新しい順）にも並べ替えられる（選ぶ欄は `select` 要素）。同順位は id 順。パターン別の内訳（その教材のパターン。年表は年号入力・年号 4 択・出来事 4 択、語彙は意味 4 択・言葉 4 択、英単語は意味 4 択・英単語 4 択と 1.4 からつづり入力、日本地理は名前 4 択・名前入力）は行を展開して表示する。
3. 履歴: 選んだ教材のセッション（`deckId` で絞る）ごとに日時・モード・範囲・パターン・正答数 / 回答済み数を、開始の新しい順に一覧表示する。中断したセッションはその旨を示す。回答 0 件のセッション（回答せずに終了したもの）は出さない。

記録の管理は成績の画面には置かず、ホームの下部から開く記録の管理の画面（5.6 節）で行う。

正答率の定義（すべて共通）: 対象の回答の正解数 ÷ 回答数。通常と復習を合算する。回答数 0 の項目・単位は「未回答」と表示し、正答率順では回答済みの後ろに置く。

## 9. ビルドと配布

### 9.1 前提

- Node.js の LTS 版と npm。Cloudflare のアカウント（無料プラン）。
- `wrangler` は devDependency として入れる。初回だけ利用者が `npx wrangler login` でブラウザ認証する。
- 実際の手順と配信の情報は `docs/operations.md` にまとめる。

### 9.2 ビルドとデプロイ

- `npm run build`: `scripts/build-data.ts` で全教材の CSV を検証して `decks.json` を生成し、Vite でビルドして `dist/` に出す。
- 教材データ（`decks.json`）は 1.4.1 から Vite の `build.rolldownOptions.output.codeSplitting` で本体とは別のチャンク（`assets/decks-*.js`）に分け、本体の JS を Vite の警告の目安（500 kB）の下に保つ。本体はデータのチャンクをハッシュ付きの名前で import するので、データが変わると本体も変わるが、本体だけの更新ではデータのチャンクを取り直さずに済む。
- Service Worker は 1.4.1 から `src/sw.ts`（`vite-plugin-pwa` の `injectManifest`）。中身は従来の生成物と同じ事前キャッシュ（`precacheAndRoute` 相当。`cleanupOutdatedCaches`、`index.html` への `NavigationRoute`、`SKIP_WAITING` の受け付け）に、読み込みの進み具合の通知（6.6 節）を足したもの。`workbox-precaching`・`workbox-routing`・`workbox-core` を devDependency に明記し、Service Worker のビルドの `target` も本体と同じ `safari15` にする。
- 事前キャッシュの対象（`globPatterns`）に `webp` を足し、`public/geography/` の地図 310 枚（約 10 MB）を含める（1.5）。初めて開いたときの取得と、画像を差し替えた版への更新は 10 MB 分だけ長くなる。iOS 16 までの配信元ごとの保存の上限は 1 GB で、問題にならない。
- `npm run deploy`: `npm run build` の後に `wrangler deploy` を実行する。`wrangler.jsonc` は静的アセットの配信だけを定義する（`assets.directory` = `dist`、`not_found_handling` = `single-page-application`）。
- `public/_headers` で配信時の応答ヘッダーを付ける。CSP は同一の配信元だけを許可し、`frame-ancestors 'none'` で埋め込みを禁止する。`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy: camera=(), microphone=(), geolocation=()`、`X-Robots-Tag: noindex` も付ける。`vite preview` にも同じファイルから読み込んだヘッダーを付け、e2e で CSP 違反がないことを確かめる。開発サーバーには、React Refresh のインラインスクリプトが CSP で止まるため付けない。
- worker 名は `qloop`。公開 URL は https://qloop.na3.workers.dev（`na3` は Cloudflare アカウントのサブドメイン）。URL を知った人は誰でも使ってよいが、広報はせず、検索エンジンにも載せない。`index.html` に `<meta name="robots" content="noindex">` を置き、応答ヘッダーでも noindex を付ける（`robots.txt` でクロールを拒否すると noindex が読まれず URL だけ載りうるので、`robots.txt` は置かない）。独自ドメインを使う場合は後から足せるが、URL が変わると各端末でホーム画面への再追加と成績の書き出し・読み込みが必要になる。
- 認証（Cloudflare Access など）は掛けない。配信するのはアプリ本体と教材データだけで、学習データは端末から出ない。

### 9.3 版の管理

- `package.json` の `version` を版の正本とし、配布する変更の PR で上げる。アプリのホーム画面に表示する。
- 版の上げ方: 不具合の修正、既存の機能の改良、データの更新は `npm version patch --no-git-tag-version`（ホームの構成と復習から外す条件を改めた 1.1.1 など）、機能の追加は `npm version minor --no-git-tag-version`（年号 4 択を足した 0.2.0 など）、大きな節目や互換性に関わる変更（URL が変わるなど、それまでの記録がそのままでは引き継がれない変更）は `npm version major --no-git-tag-version`（v1 の機能がそろい、動作保証の下限の iPhone 7 で確かめた時点の 1.0.0 など）。
- Service Worker はビルドのたびに事前キャッシュの一覧が変わるので、版を上げ忘れても更新自体は配信される。
- 1.0.0 から、リリースのたびに `CHANGELOG.md` に変更を書き、配信した main のコミットにタグ `vX.Y.Z` を打って GitHub Release を作る。手順は `docs/operations.md` の 2 章にある。

### 9.4 iOS 15.8 の Safari で守ること

- `build.target` は `safari15`。
- 使わないもの: CSS のネスト、コンテナクエリ、`:has()`、`dialog` 要素の `showModal`（ダイアログは自前の部品）。CSS の `text-size-adjust` も使わない（`safari15` 向けの最小化で接頭辞付きの指定が消え、iOS が解釈しない指定だけが残るため）。
- `navigator.share` のファイル共有は Safari 15 で使えるが、対応判定をしてダウンロードリンクに切り替える。共有は利用者の操作の直後に呼ぶ（5.6 節）。
- Service Worker、IndexedDB、Web App Manifest（`display: standalone`）、`apple-touch-icon`、`apple-mobile-web-app-capable` は使える。
- 画面は縦向きの iPhone 幅（375px）を基準にし、横スクロールを出さない。
- 画像は WebP（iOS 14 以降で表示できる）。AVIF は iOS 16 からなので使わない。`loading="lazy"` は iOS 15.4 から使える。

### 9.5 端末の導入（手順は `docs/operations.md`）

- iPhone: Safari で URL を開く → 共有 → 「ホーム画面に追加」。以後はホーム画面のアイコンから起動する。
- iOS では、ホーム画面のアプリと Safari のタブは保存場所が別で、Safari で選んだ設定や成績はアプリに引き継がれない（WebKit の設計どおりの動き）。学習はホーム画面のアプリで行う。
- スクリーンタイムの Web 制限で、許可したサイトだけにしている端末では、この URL を許可リストに入れる。
- 更新は配信するだけ。端末側の作業はない。
- 端末の入れ替え時は、旧端末で書き出した JSON を新端末で読み込む。
