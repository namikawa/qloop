# 運用手順

QLoop の配信と、端末での使い方をまとめる。設計上の決定は `docs/design.md` の 9 章にある。

## 1. 配信の情報

| 項目 | 内容 |
|---|---|
| 公開 URL | https://qloop.na3.workers.dev |
| 配信 | Cloudflare Workers の静的アセット配信（Worker 名 `qloop`） |
| Cloudflare アカウント | `namikawa`（個人のアカウント。この Mac の wrangler でログイン済み） |
| 料金 | 静的ファイルの配信だけなので無料。Workers の有料プランは不要 |
| 初回デプロイ | 2026-10-11（版 0.1.0） |

- 使い始めた端末がある間は URL を変えない。変えると、各端末でホーム画面への再追加と成績の移し替え（5 章）が必要になる。`na3` はアカウントのサブドメインで、このアカウントの全 Worker に共通。
- 認証は掛けていない。検索エンジンには `index.html` の noindex で載せない。学習の記録は端末の外に出ない。
- 版ごとの別 URL（Preview URLs）は wrangler の既定で無効。公開されるのは上の URL だけ。

## 2. デプロイ

前提: Node.js 22 以上。配布する変更の PR で `package.json` の版を上げておく（`npm version patch --no-git-tag-version`）。

1. main を最新にする。依存が入っていなければ `npm ci` を実行する。
2. ログインを確かめる。

   ```
   npx wrangler whoami
   ```

   アカウント `namikawa` が出れば準備済み。ログインしていなければ `npx wrangler login` を実行し、開いたブラウザで許可する。
3. デプロイする。CSV の検証、ビルド、アップロードの順に進み、最後に公開 URL が出る。

   ```
   npm run deploy
   ```

4. 配信後の確認をする（2.1）。

### 2.1 配信後の確認

- ブラウザで公開 URL を開き、ホーム画面の下部の版が上げた版になっていることを確かめる。
- 必要なら主要なファイルを確かめる。どれも 200 が返り、`index.html` に noindex が入っていればよい。

  ```
  curl -sI https://qloop.na3.workers.dev/ | head -1
  curl -sI https://qloop.na3.workers.dev/sw.js | head -1
  curl -sI https://qloop.na3.workers.dev/manifest.webmanifest | head -1
  curl -s https://qloop.na3.workers.dev/ | grep noindex
  ```

- `/index.html` は `/` への転送（307）になる。Service Worker は転送の印を外した形で事前キャッシュするので、オフライン起動には影響しない（2026-10-11 に本番の URL で WebKit を使って確認）。

## 3. 端末への導入

1. iPhone の Safari で公開 URL を開く。上部に「ホーム画面に追加」を促す帯が出る。
2. 共有ボタンから「ホーム画面に追加」を選ぶ。
3. 以後はホーム画面の QLoop のアイコンから起動する。帯が出なければ、ホーム画面のアプリとして動いている。

- iOS では、ホーム画面のアプリと Safari のタブは保存場所が別。Safari で選んだ設定や成績はアプリに引き継がれないので、学習はホーム画面のアプリで行う。
- Safari のタブで使い続けると、7 日間そのサイトに触れなかったときに保存データが消えることがある（Safari の規則）。ホーム画面のアプリはこの影響を実質受けない。
- スクリーンタイムで、Web サイトを許可したものだけに制限している端末では、公開 URL を許可するサイトに加える。

## 4. 更新

デプロイの後、各端末で新しい版に切り替える。0.1.1 からは、ホーム画面の下部に「アプリを更新」のボタンがある。

0.1.1 以降の端末:

1. ホーム画面の下部の「アプリを更新」を押す。
2. 「新しい版を読み込んでいます」と出たあと、画面が読み込み直されて新しい版になる。「最新の版です」と出たときは、もう新しい版になっている。
3. ホーム画面の下部の版が上がっていることを確かめる。

- 「確認できませんでした」と出たら、通信できる場所でもう一度押す。
- 起動したときに「新しいバージョンがあります」の帯が出ていれば、帯の「更新」を押してもよい。

0.1.0 の端末（ボタンが無い）:

1. アプリを開いていたら、完全に終了する。ホームボタンのある機種はホームボタンを 2 回押し、無い機種は画面の下端から上へスワイプして止める。アプリの一覧で QLoop を上へはらう。
2. ホーム画面のアイコンから開き、ホーム画面のまま数秒待つ。0.1.0 は起動したときにだけ新しい版を探し、読み込みは裏で進む。
3. 「新しいバージョンがあります」の帯が出たら「更新」を押す。
4. ホーム画面の下部の版が上がっていることを確かめる。

- 帯が出ないときは、1 と 2 をもう一度行う。

どちらの場合も、学習の途中で勝手に新しい版へ切り替わることはない。端末側でほかに行う作業はない。

## 5. 成績のバックアップと端末の入れ替え

- 書き出し: 「成績」の「記録の管理」で「書き出し」を押し、続けて「共有して保存」から「"ファイル"に保存」などを選ぶ。共有が使えない環境では「ファイルを保存」になる。ファイル名は `qloop-progress-日付.json`。
- 読み込み: 新しい端末のアプリで「読み込み」を押し、書き出したファイルを選ぶ。確認の後に、その端末の記録と出題設定がファイルの内容に置き換わる。
- 記録は端末の中にだけある。区切りのよいところで書き出しておく。
- 「リセット」は確認の後に、その端末の記録と出題設定をすべて消す。元に戻せない。

## 6. 動作確認

### 6.1 確認の手順

新しい端末に入れたときや、大きな変更を配布したときに確かめる。

1. Safari で公開 URL を開くと、上部に「ホーム画面に追加」を促す帯が出る。
2. 共有ボタンから「ホーム画面に追加」を選んで追加できる。
3. ホーム画面のアイコンから起動すると帯が消え、出題できる出来事の件数と版が出る。
4. 「出題」で年号入力を選んで数問答え、「終了」で結果まで進める。入力欄では数字のキーボードが出る。
5. アプリを完全に終了し、機内モードで起動しても、ホーム画面が開いて出題を始められる。このとき「アプリを更新」を押すと「確認できませんでした」と出る。
6. 機内モードを戻すと、「復習」に間違えた問題が出る。「アプリを更新」を押すと「最新の版です」と出る。
7. 「成績」の「書き出し」から「共有して保存」で、ファイル App に保存できる。
8. 同じ画面の「読み込み」で保存したファイルを選ぶと、確認が出る。読み込んでも、直前に書き出したファイルなら記録は変わらない。

### 6.2 確認の記録

| 日付 | 端末 | 版 | 結果 |
|---|---|---|---|
| 2026-10-11 | WebKit（Mac 上の Playwright） | 0.1.0 | 本番の URL で、事前キャッシュとオフライン起動を確認 |
| 2026-10-11 | iPhone 16 Pro | 0.1.0 | 6.1 の手順の 1〜8 で問題なし（5 と 6 の「アプリを更新」は 0.1.1 から） |
| 未実施 | iPhone 7（iOS 15.8） | | 動作保証の下限。iOS 15 の端末で確かめる |
