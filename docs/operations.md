# 運用手順

QLoop の配信と、端末での使い方をまとめる。設計上の決定は `docs/design.md` の 9 章にある。

## 1. 配信の情報

| 項目 | 内容 |
|---|---|
| 公開 URL | https://qloop.na3.workers.dev |
| 配信 | Cloudflare Workers の静的アセット配信（Worker 名 `qloop`） |
| Cloudflare アカウント | `namikawa`（個人のアカウント。この Mac の wrangler でログイン済み） |
| 料金 | 静的ファイルの配信だけなので無料。Workers の有料プランは不要 |
| 初回デプロイ | 2026-10-11（版 0.1.0） |

- 使い始めた端末がある間は URL を変えない。変えると、各端末でホーム画面への再追加と成績の移し替え（5 章）が必要になる。`na3` はアカウントのサブドメインで、このアカウントの全 Worker に共通。
- 認証は掛けていない。検索エンジンには `index.html` の noindex で載せない。学習の記録は端末の外に出ない。
- 版ごとの別 URL（Preview URLs）は wrangler の既定で無効。公開されるのは上の URL だけ。

## 2. リリースとデプロイ

リリースは、版を上げた変更を main にマージし、main から配信して、タグと GitHub Release を作ること。手順中の `X.Y.Z` は、リリースする版（例: `1.0.0`）に読み替える。

前提: Node.js 22 以上。タグと GitHub Release は、git と GitHub CLI（`gh`。ログイン済み）で作る。

1. 配布する変更の PR で、`package.json` の版を上げる（不具合の修正、既存の機能の改良、データの更新は `npm version patch --no-git-tag-version`、機能の追加は `npm version minor --no-git-tag-version`、大きな節目や互換性に関わる変更は `npm version major --no-git-tag-version`。決まりは `docs/design.md` の 9.3 節）。
2. 同じ PR で、`CHANGELOG.md` に新しい版の節を足す（2.2）。
3. マージした後、main を最新にする。依存が入っていなければ `npm ci` を実行する。
4. ログインを確かめる。

   ```
   npx wrangler whoami
   ```

   アカウント `namikawa` が出れば準備済み。ログインしていなければ `npx wrangler login` を実行し、開いたブラウザで許可する。
5. デプロイする。CSV の検証、ビルド、アップロードの順に進み、最後に公開 URL が出る。

   ```
   npm run deploy
   ```

6. 配信後の確認をする（2.1）。
7. main の先頭のコミットにタグを打って push する。

   ```
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

8. GitHub Release を作る。ノートは `CHANGELOG.md` のその版の節をそのまま使い、コミットしない一時ファイルに置く。

   ```
   gh release create vX.Y.Z --title "vX.Y.Z" --notes-file <一時ファイル>
   ```

- マージの前に実機で確かめたいときは、作業中の worktree から `npm run deploy` してよい（0.3.0 で実施）。そのときは、ほかの端末も開けばその版になる。マージした後は、main から配り直して、本番を main と同じにする。

### 2.1 配信後の確認

- ブラウザで公開 URL を開き、ホーム画面の下部の版が上げた版になっていることを確かめる。
- 必要なら主要なファイルを確かめる。どれも 200 が返り、`index.html` に noindex が入り、CSP の応答ヘッダーが返ることを確かめる。

  ```
  curl -sI https://qloop.na3.workers.dev/ | head -1
  curl -sI https://qloop.na3.workers.dev/sw.js | head -1
  curl -sI https://qloop.na3.workers.dev/manifest.webmanifest | head -1
  curl -s https://qloop.na3.workers.dev/ | grep noindex
  curl -sI https://qloop.na3.workers.dev/ | grep -i content-security-policy
  ```

- `/index.html` は `/` への転送（307）になる。Service Worker は転送の印を外した形で事前キャッシュするので、オフライン起動には影響しない（2026-10-11 に本番の URL で WebKit を使って確認）。

### 2.2 CHANGELOG の書き方

- `# 変更履歴` のすぐ下に `## [X.Y.Z] - YYYY-MM-DD` の節を足す（新しい版が上）。日付は配信する日。
- 利用者に影響する変更だけを、`### 追加`・`### 変更`・`### 修正` に分けて書く。書くのは振る舞いの変更で、docs だけの変更、見た目と動きの変わらない整理、画面の説明文の追加のような細かい変更は書かない。
- 書くのは「何がどう変わったか」だけで、1 変更 1 行に収める。理由や仕様の詳細は docs に書き、CHANGELOG には持ち込まない。
- 末尾のリンクの定義に `[X.Y.Z]: https://github.com/namikawa/qloop/releases/tag/vX.Y.Z` を足す（新しい版が上）。

## 3. 端末への導入

1. iPhone の Safari で公開 URL を開く。上部に「ホーム画面に追加」を促す帯が出る。
2. 共有ボタンから「ホーム画面に追加」を選ぶ。
3. 以後はホーム画面の QLoop のアイコンから起動する。帯が出なければ、ホーム画面のアプリとして動いている。

- iOS では、ホーム画面のアプリと Safari のタブは保存場所が別。Safari で選んだ設定や成績はアプリに引き継がれないので、学習はホーム画面のアプリで行う。
- Safari のタブで使い続けると、7 日間そのサイトに触れなかったときに保存データが消えることがある（Safari の規則）。ホーム画面のアプリはこの影響を実質受けない。
- スクリーンタイムで、Web サイトを許可したものだけに制限している端末では、公開 URL を許可するサイトに加える。

## 4. 更新

デプロイの後、各端末で新しい版に切り替える。

1. ホーム画面の下部の「アプリを更新」を押す。
2. 「新しい版を読み込んでいます」と出たあと、画面が読み込み直されて新しい版になる。「最新の版です」と出たときは、もう新しい版になっている。
3. ホーム画面の下部の版が上がっていることを確かめる。

- 「確認できませんでした」と出たら、通信できる場所でもう一度押す。
- 起動したときに「新しいバージョンがあります」の帯が出ていれば、帯の「更新」を押してもよい。

学習の途中で勝手に新しい版へ切り替わることはない。端末側でほかに行う作業はない（アイコンが変わる版は 4.1）。

### 4.1 アイコンが変わる版（0.3.0）

0.3.0 でアイコンを変えた。iOS は、ホーム画面に追加したときのアイコンを使い続けることがある。上の手順で 0.3.0 にしてもアイコンが古いままなら、次の順に追加し直す。ホーム画面のアプリを削除すると記録も消える場合があるので、先に書き出し、新しく追加したアプリに読み込んでから、古いアプリを消す。

1. 今のアプリで「成績」の「全体」にある「記録の管理」から「書き出し」を押し、ファイルに保存する（5 章）。
2. Safari で公開 URL を開き、共有ボタンから「ホーム画面に追加」を選ぶ（3 章）。
3. 新しく追加したアプリを開き、「成績」の「全体」にある「記録の管理」の「読み込み」で、1 のファイルを読み込む。
4. 新しいアプリに記録が移ったことを確かめてから、古いアイコンのアプリをホーム画面から削除する。

## 5. 成績のバックアップと端末の入れ替え

- 書き出し: 「成績」の「全体」にある「記録の管理」で「書き出し」を押し、続けて「共有して保存」から「"ファイル"に保存」などを選ぶ。共有が使えない環境では「ファイルを保存」になる。ファイル名は `qloop-progress-日付.json`。
- 読み込み: 新しい端末のアプリで「読み込み」を押し、書き出したファイルを選ぶ。確認の後に、その端末の記録と出題設定がファイルの内容に置き換わる。
- 記録は端末の中にだけある。区切りのよいところで書き出しておく。
- 「リセット」は確認の後に、その端末の記録と出題設定をすべて消す。元に戻せない。

## 6. 動作確認

### 6.1 確認の手順

新しい端末に入れたときや、大きな変更を配布したときに確かめる。

1. Safari で公開 URL を開くと、上部に「ホーム画面に追加」を促す帯が出る。
2. 共有ボタンから「ホーム画面に追加」を選んで追加できる。
3. ホーム画面のアイコンから起動すると帯が消え、出題できる出来事の件数と版が出る。
4. 「出題」で年号入力を選んで数問答え、「終了」で結果まで進める。入力欄では数字のキーボードが出る。「わからない」を押すと答えが出て先へ進める。年号 4 択と出来事 4 択でも同じように答えられる。ホームで語彙に切り替え、意味 4 択と言葉 4 択でも答えられ、判定の帯に読みが出ることを確かめる。
5. アプリを完全に終了し、機内モードで起動しても、ホーム画面が開いて出題を始められる。このとき「アプリを更新」を押すと「確認できませんでした」と出る。
6. 機内モードを戻すと、「復習」に間違えた問題が出る。「アプリを更新」を押すと「最新の版です」と出る。
7. 「成績」の「全体」の「書き出し」から「共有して保存」で、ファイル App に保存できる。
8. 同じ画面の「読み込み」で保存したファイルを選ぶと、確認が出る。読み込んでも、直前に書き出したファイルなら記録は変わらない。
9. 見た目を変えた版では、ホーム画面のアイコン、上部の時刻の表示の色、判定の帯が下から出る動き、数字のキーボードを出したときに入力欄が下の帯で隠れないことも確かめる。
