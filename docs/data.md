# 教材データの手引き

教材データを足したり直したりするときの基準と手順をまとめる。1〜5 章は日本史年表（`data/decks/japanese-history/` の `core.csv` と `pool.csv`）、6 章は語彙（`data/decks/japanese-vocabulary/` の `core.csv` と `pool.csv`。1.1 で追加）、7 章は英単語（`data/decks/english-words/` の `core.csv`。1.3 で追加）。列の定義と自動の検証は `docs/design.md` の 5 章にある。

## 1. 2 つのファイル

| ファイル | 中身 | 件数（2026-10-11） | id |
|---|---|---|---|
| `core.csv` | 基本の年表。利用者がまとめ、題名を加筆したもの | 129 | `jh-0001`〜`jh-0129` |
| `pool.csv` | 追加データ。中学受験の範囲の出来事を作成したもの | 271（うち `高校` 29） | `jh-0130`〜`jh-0401`（`jh-0195` は削除済みで欠番） |

- 出題設定の「出題する出来事」の既定は「基本の年表のみ」で、`core.csv` だけから出題する。「すべて」を選ぶと、`pool.csv` の `高校` 以外の行も出題する。
- 出来事 4 択の誤答の候補には、両方のファイルの全行（`高校` の行を含む）を使う。
- 復習と成績は、出題設定によらず `core.csv` と `pool.csv` の `高校` 以外の行（371 件）を対象にする。

## 2. 正誤の基準（絶対の方針）

> このデータにおける「正しさ」は、歴史的な史実ではなく、現代の中学受験・高校受験で出題される問題での正解とする。

データの作成と修正、文書の記述、レビューの依頼、レビュー指摘の採否は、すべてこの基準で行う。

- 年号と表記（用語・人物名・題名の言い回し）は、受験の問題で正解とされるものを正とする。`level` が空（中学）の行は中学受験、`高校` の行は高校受験の正解を基準にする。中学受験の対象は関東圏の易しい〜早慶/MARCH 付属の私立中で、一般的な中学受験の出題傾向と小学校の教科書で標準的に扱われるものを基準にする。
- 史実や歴史学的な解釈が受験の正解と違う場合も、受験の正解を採る。史実と違うことだけを理由に直さない。
  - 例: 建武の新政は 1334 年。後醍醐天皇が新政を始めたのは 1333 年だが、受験の正解は 1334 年で、1333 年は別解にもしない。
  - 例: 禁教令は 1612 年。全国に広げた 1613 年は別解にしない。
- 受験の正解と違う年を覚えさせると実害が出る。データの追加と修正は、4 章の手順で特に慎重に点検する。

## 3. 列の使い分け

- `alt_years`（別解）: 中学受験の出題で年が 2 通りに分かれていて、どちらを答えても正解とされる出来事にだけ付ける。題名全体に対して正しいと言える年だけを書く。「鎌倉幕府の成立」のように題名が複数の年を許す場合には付けられるが、「守護・地頭を置く」のように特定の行為を指す題名には付けない。受験で 1 つに決まっている出来事には付けない。年号入力では別解の年も正解にし、年号 4 択では別解の年を誤答の選択肢に出さない。
- `approx`（ごろ）と `year_label`: 受験の年表で「〜ごろ」「〜世紀」と教えられる出来事にだけ付ける。`approx` の行は年号入力と年号 4 択に出題されず、出来事 4 択だけで出る。`year_label` は年の表示の上書き（例 `5世紀ごろ`）。代表年 `year` は、その幅の中ほどの年にする（例: 紀元前 4 世紀は `-350`）。
- `era`（時代の上書き）: 時代区分表（`docs/design.md` の 5.3 節）で決まる時代が、一般的な年表の感覚と食い違う行だけに付ける。例: 1185 年の平氏の滅亡（`jh-0022`）を平安、1573 年の室町幕府の滅亡（`jh-0040`）を室町にしている。
- `level` の `高校`: 人物や出来事は中学受験の範囲でも、年号までは問われないものに付ける。`高校` の行は出題されず、出来事 4 択の誤答の候補にだけ使う。中学受験の年表に載る出来事には付けない。
- `title`: 問題文としてそのまま読める 1 文にし、1 行に 1 つの出来事だけを書く（「/」で並べない）。主体・相手・内容や目的を短く補い、受験で使う用語を入れる（例: 「聖徳太子が冠位十二階を定め、家柄にとらわれず人材を取り立てる」）。文末は辞書形（「〜する」「〜が起こる」など）で、読点は 1 つまで。長さは全角 15〜30 字を目安にし、上限は 36 字。
  - 補うときは足すだけにする。元の題名にある人物・出来事・物・場所・制度の名前と、出来事の呼び名になっている語（「鉄砲が伝来する」の「伝来」など）は、同じ表記で残す。易しい言葉を難しい言葉に置き換えない。正式名を示したいときは、元の語を残してかっこ書きで補う（例: 「日本地図（大日本沿海輿地全図）」）。
  - 出来事 4 択では `core.csv` と `pool.csv` の題名が同じ画面に並ぶ。両方の長さと詳しさをそろえ、長さで正解が見分けられないようにする。
  - 答えの年がわかる手がかり（西暦、年数、語呂合わせ、「○世紀」など）は入れない。別の年の出来事の名前は、受験で標準的に結びつけて教える因果のときだけ出す。
  - `core.csv` と同じ出来事（別の表記や、同じ年の同じ事件の別の側面）は `pool.csv` に入れない。特定の教材の文をそのまま写さない。

## 4. データを足す・直す手順

1. CSV を直接編集する。id は既存の最大の続きから振る。一度付けた id は変えず、削除した id は再利用しない（`docs/design.md` の 5.5 節）。
2. `npm run data` で検証する。id と題名の重複、各列の値、`core.csv` の全行で出来事 4 択の誤答候補が 3 件以上あることを確かめ、失敗したら全エラーを行番号付きで出す。
3. `npm test` と `npm run lint` を通す。
4. 点検する。外部レビューを使うときは、依頼文の冒頭に 2 章の定義を書き、史実と違うことだけを理由にした指摘は不要と明記する。5 章の確定した判断も「再提出不要」として渡す。追加データ（D2）は次の 3 巡で指摘が無くなった。
   1. 全行の年号・題名・時代・`core.csv` との重なり・形式を点検する。
   2. 受験の基準で全行を見直す（別解・ごろ・`高校` の付け方、受験の用語、足りない定番の出来事）。
   3. 変更・追加した行だけを確かめる。
5. 利用者が内容を確認してから PR にする。

利用者の年表を取り込むとき（`core.csv`）:

- 利用者から受け取るのは「番号・項目・年代」などの列を持つ CSV。整形は実装側で行い、利用者に列の追加を求めない。
- 「/」で複数の出来事が並ぶ行は 1 件ずつに分ける。分けたときに述語が欠ける題名は補う（例: 「サンフランシスコ平和条約/日米安全保障条約が結ばれる」は、2 件それぞれに「が結ばれる」を付ける）。
- 「〜ころ」と書かれた出来事は、題名から「ころ」を除いて `approx` を付ける（例: 「高度経済成長期が始まるころ」は「高度経済成長期が始まる」）。
- 取り込んだ題名は、3 章の書き方に合わせて加筆する。初期データと追加データは、2026-10-11 に全行の題名をこの書き方で加筆した。
- 年表の改訂で取り込み直すときは、既存の `core.csv` と出来事を照合して差分だけを足し、全件を振り直さない。題名は加筆で変わっているので、照合は年と出来事の中身で行う。

### 6.1 2 つのファイル

| ファイル | 中身 | 件数（2026-10-14） | id |
|---|---|---|---|

### 6.2 正誤の基準（絶対の方針）

> このデータにおける「正しさ」は、辞書の記述や語源ではなく、現代の中学受験・高校受験で出題される問題での正解（意味と表記）とする。

データの作成と修正、文書の記述、レビューの依頼、レビュー指摘の採否は、すべてこの基準で行う（2 章と同じ）。

- 意味は、受験の問題で正解とされる意味を書く。辞書に複数の意味があっても、受験で問われる意味にしぼる。本来の意味と広まった使い方が違う言葉は、受験で正解とされる方を採る。例: 「情けは人のためならず」は「人に親切にしておけば、めぐりめぐって自分によい報いが返ってくる」。
- 表記（漢字とかなの使い分け、送りがな）は、中学受験の教材で標準的な表記にする。同じ言葉を表記違いで 2 行入れない。
- 中学受験の対象は 2 章と同じ（関東圏の易しい〜早慶/MARCH 付属の私立中）。中学受験と高校受験で語彙の問題に大きな差は無いので、ほとんどの行は `level` を空にし、中学受験で問われない言葉と、問われるか確かめられない言葉にだけ `高校` を付ける。
- 受験の正解と違う意味を覚えさせると実害が出る。追加と修正は 6.4 の手順で慎重に点検する。

### 6.3 列の使い分けと書き方

- `word`: 1 つの言葉だけを書く。受験の教材で見出しになる形にする（例: 「足が棒になる」「油を売る」）。カンマと引用符は使わない。
- `meaning`: 1 文で、全角 25 字までを目安にする（上限 30 字）。文末は「〜こと」でそろえる。名詞の言葉も「〜のこと」で終え、`core.csv` と `pool.csv` でそろえる。読点は 1 つまで。
  - 言葉の中の語をそのまま意味に使わない（例: 「油を売る」の意味に「油」を入れない）。意味を言うのに必要なときだけ使ってよい（例: 「足が棒になる」の「足」）。
  - 意味 4 択では `core.csv` と `pool.csv` の意味が同じ画面に並ぶ。長さと詳しさをそろえ、長さや文体で正解が見分けられないようにする。
  - 特定の辞書や教材の文をそのまま写さず、自分の言葉で書く。
  - 読み手は訓練された中学受験生とする。受験の教材で使う程度の言葉（例: 「巧み」「謙虚」）は、それより易しく言い換えない。
- `category`: 種類の一覧（`docs/design.md` の 5.7 節）の値。1.1 は `慣用句` だけ。
- `reading`: 言葉の読みをひらがなで書く。問題文には出さず、判定の後と結果・成績の一覧に出す。読み方が 2 通りある言葉は、受験の教材で標準的な方を 1 つ書く。
- `level` の `高校`: 中学受験の問題で問われない言葉と、問われるか確かめられない言葉に付ける。`高校` の行は出題されず、誤答の候補にだけ使う。
- `similar`: 意味が近く、4 択で並んだときにどちらを選んでも正解と言える言葉の id を書く（例: 「舌を巻く」と「目を見張る」のような、驚いて感心する意味の組）。片方の行に書けば両方向に効く。迷ったら書く（除外が多くても害は小さく、候補が 3 件を切れば検証で止まる）。ただし、同じ系統の言葉でもニュアンスが違えば書かない（例: 「口をぬぐう」と「面の皮が厚い」）。思い違いをされやすいこと（例: 「爪に火をともす」を貧しさの意味と取る）は、書く理由にしない。

### 6.4 データを足す・直す手順

4 章と同じ段取りで、点検の観点が違う。

1. CSV を直接編集する。id は既存の最大の続きから振り、付け替えない。
2. `npm run data` で検証する（id・言葉・意味の重複、種類と `level` の値、意味の長さ、`similar` の参照先、`core.csv` の全行で同じ種類の誤答候補が 3 件以上あること）。
3. `npm test` と `npm run lint` を通す。
4. 点検する。外部レビューを使うときは、依頼文の冒頭に 6.2 の定義を書き、辞書や語源と違うことだけを理由にした指摘は不要と明記する。6.5 の確定した判断も「再提出不要」として渡す。
   1. 全行の意味・表記・種類・読み・`core.csv` との重なり・形式を点検する。意味が近い組に `similar` の漏れがないかも見る。
   2. 受験の基準で全行を見直す（受験で問われる意味になっているか、`高校` の付け方、足りない定番の言葉）。
   3. 変更・追加した行だけを確かめる。
5. 利用者が内容を確認してから PR にする。

利用者の一覧を取り込むとき（`core.csv`）:

- 利用者から受け取るのは「言葉・意味」（あれば「種類」）の列を持つ一覧。整形は実装側で行い、利用者に列の追加を求めない。
- id・種類・読み・`similar` はこちらで補う。意味の文末の形と長さを 6.3 に合わせて整え、変えた行は一覧にして利用者が確認する。言葉の表記は変えない（受験の標準と違うときは利用者に確認する）。
- 追加データ（`pool.csv`）は、重複を避けるため基本データを受け取ってから作る。基本データと同じ言葉（表記違いを含む）は入れず、意味が近い言葉は `similar` を書くか入れない。種類ごとに、基本データの各行の誤答候補が十分になるようにする（同じ種類で 5 件以上が目安）。

追加データに入れる言葉:

- 受験の教材で慣用句として扱われることがある言葉は入れる。教材によってことわざや故事成語とされる言葉も入れる（分類を問う出題は無く、意味を覚える必要は変わらないため）。ことわざとしてしか扱われない言葉（例: 猫に小判、急がば回れ）と四字熟語（例: 一石二鳥）は入れない（言葉 4 択は「この意味の慣用句は？」と出題するため）。
- 1 つの言葉は 1 行で、種類は 1 つ。ことわざの種類を足すときに、1 つの言葉を両方の種類で出せるようにするかを決める。
- 中学受験で問われるか確かめられない言葉は、削らずに `高校` を付けて入れる。
- 2026-10-14 に入れた追加データ（233 件）は、3 巡の点検の後に利用者が内容を確認した。

## 7. 英単語のデータ

教材「英単語」（`data/decks/english-words/core.csv`）の手引き。列の定義と自動の検証は `docs/design.md` の 5.8 節、出題と誤答の選び方は 6.11 節にある。年表・語彙と違い、利用者が用意する本とレッスンの一覧をレッスンごとに段階的に足す。2026-10-15 に最初のデータとして STAGE2 Lesson 4 の 84 件（`en-0001`〜`en-0084`）を入れた。同日に STAGE2 Lesson 5 の 97 件（`en-0085`〜`en-0181`）を足した（1.3.1）。

### 7.1 1 つのファイル

| ファイル | 中身 | id |
|---|---|---|
| `core.csv` | 本（`book`）とレッスン（`lesson`）ごとの英単語の一覧。レッスンを足すときは行を追記する | `en-0001` から、足した順に続ける |

- 追加データ（`pool.csv`）は無い。出題設定に「基本のみ / すべて」の切り替えは出ず、全行を出題する。
- 誤答の候補には、登録済みの全レッスンの行を使う（`docs/design.md` の 6.11 節の除外規則と品詞の優先）。
- 復習と成績は全行を対象にする。

### 7.2 正しさの基準

> このデータにおける「正しさ」は、利用者が用意した一覧の意味と表記とする。

- 意味・表記・品詞・本・レッスンは、利用者の一覧のとおりに入れる。辞書と違うことだけを理由に直さない。
- 直すのは、一覧の明らかな誤記と、形式の都合（意味の上限、記号の統一）だけで、直した行は一覧にして利用者が確認する。

### 7.3 列の使い分けと書き方

- `word`: 一覧の表記のまま。大文字（`Pacific`）、ピリオド（`Never mind.`）、アポストロフィ（`here's`）、穴（`What ... for?`）も残す。同じ英単語かどうかは、大文字小文字・前後と連続する空白・全角と半角・アポストロフィの種類・末尾の記号を無視して比べる（`docs/design.md` の 6.11 節）。穴のある行はつづり入力の出題元にならず、別解にもならない。
- `meaning`: 一覧の文面のまま。複数の意味の「、」区切り、「～」「…」、かっこの注記（`（線で）～を描く`、`〈劇などの〉場面`）、文末の「。」もそのまま。数字は半角にする（一覧が全角でも直す。例: secondly の「第2に」）。上限は 50 字で、目安は 40 字。縮めない（意味の注記を落とさない）。
- `pos`: 一覧の品詞のまま（`名詞`・`動詞`・`形容詞`・`副詞`・`代名詞`・`前置詞`・`接続詞`・`助動詞`・`間投詞`・`冠詞`・`数詞`。複数は「・」でつなぐ）。熟語・表現は空のままにする。一覧に無い品詞が出てきたら、コードの一覧と略記を足す。
- `book`・`lesson`: 利用者の指定のとおり（本は `STAGE1`・`STAGE2`・`STAGE3`、レッスンは番号）。
- `similar`: 意味が近く、4 択でどちらを選んでも正解と言える組に書く（例: somebody と anybody、anything と nothing）。同じ `meaning` の行（liberty と freedom の「自由」など）は書かなくても同じ答えとして扱われ、`similar` は同じ答えの集まり（同じ意味と `similar` でつながる全行。`docs/design.md` の 6.11 節）の全部に効くので、組のどれか 1 行に書けばよい。4 択では集まりの意味と英単語を誤答に出さない。つづり入力の正解には使わない（正解は、カードの文（品詞付きの意味）が同じ行の `word` だけ）。迷ったら書く（除外が多くても害は小さい）。品詞の違う組は、品詞の優先で互いの誤答に出にくいので、実データで並ぶかを確かめてから決める。
- 同じ `word` が別のレッスンに別の意味で載るときは、別の行（別の id）として入れる。意味 4 択では、その英単語のどの行の意味（と、それぞれの集まりの意味）も誤答に出ない。

### 7.4 レッスンを足す手順

1. 利用者から、英単語・熟語と日本語の意味と品詞の一覧と、本とレッスンの指定を受け取る。
2. 整形する。行の順はそのままにし、id は既存の最大の続きから振る。`book`・`lesson` を付け、`similar` を補う。一度付けた id は変えない（`docs/design.md` の 5.5 節）。
3. `npm run data` で検証する（id の一意、`word`・`book`・`lesson` の組の一意、各列の値、意味の長さ、`similar` の参照先、全行で意味 4 択と英単語 4 択の誤答候補（異なる表示）が 3 件以上あること）。
4. `npm test` と `npm run lint` を通す。
5. 点検する。同じ `meaning` の組と意味の近い組（`similar` の漏れ）、品詞の空欄と一覧に無い品詞、40 字を超える行、記号の揺れ（`...` と `…`、全角と半角）、前のレッスンと同じ `word` の行を見る。
6. 補った `similar`、品詞が空の行、40 字を超える行、前のレッスンと同じ `word` の行を一覧にして、利用者が内容を確認する。
7. PR にする。最初のレッスンは PR 13 に同梱した。以後は 1 レッスンか数レッスンごとのデータ PR で版を patch で上げる（`docs/operations.md` の 2 章）。
